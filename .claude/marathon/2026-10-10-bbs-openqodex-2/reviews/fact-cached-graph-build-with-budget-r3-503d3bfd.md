## Medium (1)

- **Sparse-checkout files are silently skipped and the graph still reports partial: false** — `src/lib/kit/graph.js:980` (correctness): listRepoFiles uses \`git ls-files --cached\`, which lists skip-worktree entries that a sparse checkout (common in large repos and partial clones on slow links) never writes to disk. buildGraph treats each one as a deleted file (\`e.missing\` -\> stats.missing++, continue): it is not added to not\_read, so \`partial\` stays false. Repro: a repo with src/a.js (a) and lib/b.js (calls a), \`git sparse-checkout set src\`, then \`cli.js graph --changed src/a.js\` gives partial:false, not\_read:\[\], stats.missing:1. lib/b.js is never read, and the result claims to be complete. The w-review step then allows 'nothing else calls a', which is exactly what the partial flag exists to prevent. The same applies to .claude/helpers/kit/graph.js. — fix: List the files with \`git ls-files -t\` (or check the skip-worktree bit) and put skip-worktree entries in not\_read with a reason such as 'not\_checked\_out', so partial becomes true. Keep genuinely deleted working-tree files counted as missing.

## Low (3)

- **Fact cache is written at the git top without ignoring itself, so it shows up untracked outside the installer's .gitignore rule** — `src/lib/kit/graph.js:923` (other): The cache goes to \<git top\>/.claude/kit/cache/graph. The only ignore rule is the one kit.js install appends to \<targetDir\>/.gitignore. When the suite is installed into a subfolder of a repository, that rule is anchored to the subfolder and does not cover the top-level cache. A run with --dir against a repository installed by an older kit has no rule at all. Repro: repo/app/.gitignore holds \`.claude/kit/cache/\`, then \`cd app && cli.js graph\` makes \`git status -uall\` show \`?? ../.claude/kit/cache/graph/\<sha\>.json\`. Those files can be committed by \`git add -A\`, and a top-level run of the w-review untracked-file loop puts every one of them into the review diff. — fix: When the cache folder is created, also write a \`.gitignore\` containing \`\*\` inside .claude/kit/cache/ (through guardedWrite), so the cache ignores itself wherever it lands.
- **CR-only line endings make the rest of the file a comment, so the facts are empty and get cached** — `src/lib/kit/graph.js:115` (correctness): Line comments (and the shebang skip at line 108) end only at '\n', and line counting uses only '\n'. A file with old-Mac/CR-only line endings, which JavaScript accepts as line terminators, is consumed from its first \`//\` to the end of the file. extractFacts('// h\rexport function a(){ b(); }\rfunction b(){}\r', {path:'x.js'}) returns no defs, calls or exports, with no parse\_error. This empty result is cached as if it were correct and is not listed in not\_read. — fix: Treat \r, U+2028 and U+2029 as line terminators: end // comments at any of them and count a lone \r (not followed by \n) as a new line.
- **Budget and per-file time limit use the wall clock (Date.now), which can step** — `src/lib/kit/graph.js:885` (correctness): The default clock is Date.now, which is used for both the build budget and the per-file deadline (line 250). On VMs or older hosts where NTP steps the clock, a backwards step stops the budget and the per-file limit from firing, so a pathological file or a large tree can run past --budget-ms. A forward step cuts the build at once and marks files 'budget'. — fix: Default the clock to performance.now (monotonic). It is a drop-in replacement for the clock option.
