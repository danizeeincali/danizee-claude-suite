## Medium (1)

- **Store path is wrong when run from a subdirectory: receipt/check fail with a raw ENOENT or read the wrong store** — `src/lib/kit/push-gate.js:158` (correctness): storeFile() resolves \`git rev-parse --git-common-dir\` against --show-toplevel, but git prints that path relative to the cwd (from \<repo\>/sub it prints '../.git'). Resolving it against the toplevel gives \<parent\>/.git. I reproduced this: \`push-gate check\` run from a subdirectory exits 1 with 'kit: ENOENT: no such file or directory, realpath /tmp/pgt/.git'. That is an uncaught non-KitExit error with a misleading message, so neither receipt nor check works from any subdirectory. If the parent directory happens to have a .git, the gate keys a different store: a receipt recorded at the repo root is then reported as 'no review recorded' from the subdirectory (also reproduced). Mirrored at .claude/helpers/kit/push-gate.js:158. No test covers running from a subdirectory. — fix: Use \`git rev-parse --path-format=absolute --git-common-dir\`, as workingTree() already does for --git-path, or resolve the path against the cwd instead of the toplevel. Add a test that records a receipt at the root and runs check from a subdirectory.

## Low (3)

- **A missing or unspawnable git is reported as 'not inside a git repository'** — `src/lib/kit/push-gate.js:44` (correctness): defaultGit maps a spawn failure (r.error set, status null, for example ENOENT when git is not on PATH) to code 1 with empty stderr and drops r.error. changeId's first probe then throws 'not inside a git repository', which sends the user the wrong way. Mirrored in .claude/helpers/kit/push-gate.js. — fix: When r.error is set, return or throw its message (for example, KitExit(\`cannot run git: ${r.error.message}\`)).
- **Receipt store update is an unlocked read-modify-write, and a failed write leaks its temp file** — `src/lib/kit/push-gate.js:209` (correctness): run() reads the state, builds \`previous\`, then writeAtomic renames over the file. Two receipts recorded concurrently in the same repository (for example, two worktrees sharing the common dir, which hash to the same store) lose one writer's latest/previous entries. Separately, if writeFile or rename throws, the \`\<file\>.\<pid\>.\<rand\>.tmp\` file stays in the receipts dir, and the raw fs error surfaces instead of a KitExit. — fix: Unlink the tmp file in a catch/finally and wrap the error in KitExit. Optionally take a lockfile (O\_EXCL) around the read-modify-write.
- **Closing step requires a matching --threshold but not a matching --base** — `.claude/commands/.shortcuts/w-review.md:145` (docs): The change id hashes the base. A receipt recorded without --base (merge-base with upstream, or root) and a check run with --base, or the reverse, never match. The check then reports 'only an earlier review exists, for a different version of this change', which misdescribes the situation and tells the user to re-run /w-review. The closing step only says to keep --threshold the same. Same text in src/plugins/dot-shortcuts.js:2262. — fix: Say to pass the same --base (or none) to both receipt and check, or record the base in the receipt and report a base mismatch distinctly in decide().
