## High (1)

- **innermost() is computed across all of a file's ranges together, so an enclosing definition that changed in its own lines is dropped when a nested definition also changed** — `src/lib/kit/impact.js:79` (correctness): innermost(defs, c.added) first collects every definition that overlaps any range, then removes each one that contains another hit definition. It does not check, range by range, whether the enclosing definition was changed outside the nested one. Repro (a fresh repo, either \`--diff file\` or \`--diff -\`): lib/a.js \`export function outer(){ const k = 1; function inner(){ return 1; } return k; }\`, lib/b.js \`import {outer} from './a.js'; export function user(){ return outer(); }\`; change \`const k = 1\` to \`2\` AND \`return 1\` to \`return 5\`. The output has touched=\[outer.inner\], impacted=\[\], risk low, lower\_bound false. outer's own change (its return value) and its direct caller user() are missing, with nothing to say the answer is a floor. Change only \`const k\` and outer is touched, with user() at hop 1. The same happens for a class whose field and one of whose methods both change, and the mirror .claude/helpers/kit/impact.js has the same code. — fix: Decide per changed line (or per range): for each line, take the smallest definition that contains it, and union the results. A definition then counts as touched when at least one changed line falls inside it and outside all of its children.

## Medium (1)

- **Module-level changes go unreported when the changed range also overlaps a definition** — `src/lib/kit/impact.js:106` (correctness): The module\_level check asks whether a whole merged range overlaps no definition (\`!defs.some((d) =\> overlaps(d, r))\`), but the header promises that 'a changed line outside every definition is reported as a module-level change'. When a module-level line is next to a changed definition line, the two merge into one range, and that range overlaps the definition. Repro: in lib/a.js add \`export const LIMIT = 5;\` directly above \`export function foo() {\` and change that line to \`export function foo(x = LIMIT) {\`. The output has module\_level \[\] and notes \[\], so the const change and the warning that nothing is followed from it are both missing. Adding imports at the top of a file next to a first function changed in the same diff is the common way to hit this. — fix: Check line by line: if any changed line inside a range is not covered by a definition, push the file to module\_level (for example, expand each range into its lines, or subtract the definition spans from the range).
