## Medium (2)

- **Plain --exclude=\<pattern\> is taken for an abbreviation of --exclude-existing, so the CLI refuses it with an untrue 'reads stdin' message** — `src/lib/kit/safe-git.js:129` (correctness): readsStdin only treats an exact STDIN\_LONG name as exact; any other name that is a prefix of one counts as that option. \`exclude\` is a prefix of \`exclude-existing\`, but --exclude is a real option of describe, ls-files, log, rev-list, name-rev and for-each-ref, and git matches the exact name first. Traced with git 2.43: \`cli.js safe-git --dir r -- describe --exclude=nothing --tags\`, \`ls-files --exclude=\*.o --others\`, \`log --all --exclude=refs/tags/\*\`, \`rev-list --all --exclude=refs/tags/\*\` and \`name-rev --exclude=x HEAD\` all exit 1 with 'describe with these options reads stdin: pass --input - before \`--\`'. None of them reads stdin (plain git answers \`v1-1-gb976efe\`). The message sends the user after stdin, which is the wrong cause; the only way through is to pipe empty stdin with --input -. — fix: Keep a per-subcommand exact-name set as EXACT\_SAFE does (exclude is exact for every allowed subcommand except show-ref), or count a name only when it is not itself a real option of the subcommand. Add a CLI test for \`describe --exclude=x\` and \`rev-list --all --exclude=x\`.
- **Symlink check under objects/ stops one level down: a symlinked objects/info/commit-graphs/\*.graph or commit-graph-chain is followed outside the repo** — `src/lib/kit/safe-git.js:644` (security): checkObjectsNotLinked only walks objects/ and its direct subfolders, but git also reads objects/info/commit-graphs/graph-\<hash\>.graph and commit-graph-chain, which are two levels down. Traced: clone, \`git commit-graph write --split --reachable\`, replace the .graph file with a symlink to a FIFO outside the repo, then \`cli.js safe-git --dir cg --timeout 3000 -- log --oneline -1\`. git opens the outside file and blocks until the timeout ('git log took longer than 3000 ms ... raise it with --timeout'), so every read of that repo fails after the default 60 s. A symlink to a regular file or a network path is opened the same way. The header (line 26-27) says 'any symlink inside it' is refused, and the threat model says nothing outside the repo is read. This is the round-11 fix only partly done. — fix: Walk objects/info/commit-graphs too (or recurse with a depth cap of 2 under info/), refuse a symlink there, and add a test with a symlinked split commit-graph file and chain.

## Low (1)

- **A .gitattributes in a folder whose name is not UTF-8 is never read, so its drivers are not listed** — `src/lib/kit/safe-git.js:494` (correctness): ls-files output is decoded as UTF-8, so a byte such as \xff in a folder name becomes U+FFFD. lstat of that rebuilt path fails, so the file is treated as gone from the work tree, and the cat-file lookup misses it too. Traced: a repo with \`d\xff/.gitattributes\` = \`\* filter=evil\` and \`ok/.gitattributes\` = \`\* filter=good\` gives overrides for \`good\` only. git itself reads both. No program runs, because the shadow config defines no drivers, but the header's claim that every driver in a work-tree .gitattributes git would read gets switched off does not hold. — fix: Run that ls-files with binary: true and work with the raw path bytes (Buffer paths for lstat/open, raw bytes on cat-file stdin), or refuse when a listed path does not round-trip through UTF-8.
