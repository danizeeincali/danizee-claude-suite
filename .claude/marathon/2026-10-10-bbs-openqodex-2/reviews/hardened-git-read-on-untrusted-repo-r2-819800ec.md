## High (2)

- **Repo config format.pretty + gpg.program runs a program on a plain \`log\`/\`show\`** — `src/lib/kit/safe-git.js:152` (security): STATIC\_OVERRIDES switch off log.showSignature, and checkReadArgs refuses %G in argv, but neither gpg.program/gpg.ssh.program/gpg.x509.program nor format.pretty / pretty.\<alias\> is overridden. A hostile repo with \`format.pretty=%H %G?\`, \`gpg.program=\<script\>\` and a commit that has a gpgsig header makes \`safeGit(dir, \['log','-1'\])\` or \`\['show','-s','HEAD'\]\` run the script. I reproduced this on git 2.43 with a marker file. The same happens via \`log --format=\<alias\>\` with pretty.\<alias\>=%G?, and via \`for-each-ref --format=%(signature)\`, which the %G regex does not catch. — fix: Add \`-c gpg.program=false -c gpg.ssh.program=false -c gpg.x509.program=false -c format.pretty=medium\` to STATIC\_OVERRIDES (and refuse %(signature) in argv, or rely on the gpg overrides); add a regression test with a signed-looking commit.
- **Submodule work trees run their own clean filters during status/diff/describe --dirty** — `src/lib/kit/safe-git.js:250` (security): Driver discovery reads only the outer repo's config and skips every \`.git\` dir, but status, diff, diff-files, diff-index and describe --dirty start a child git inside a checked-out submodule, which reads that submodule's .git/config and .git/info/attributes. Repro: outer repo with gitlink \`sub\`, \`sub/.git/config\` filter.zz.clean=\<script\>, \`sub/.git/info/attributes\` \`\* filter=zz\`, and sub/f rewritten with the same size and a new mtime. Each of \`status --porcelain\`, \`diff\`, \`diff-files\`, \`diff-index HEAD\` and \`describe --always --dirty\` through safeGit then created the marker. The propagated -c covers hooks and fsmonitor, but not driver names that appear only in the submodule. — fix: Pass \`--ignore-submodules=all\` (status/diff family) and \`-c diff.ignoreSubmodules=all\`, or refuse when the tree has gitlinks with a populated .git. Also scan nested .git/config and info/attributes, or refuse on nested .git dirs.

## Medium (1)

- **protocol.allow=never is overridden by repo protocol.\<name\>.allow; GIT\_NO\_LAZY\_FETCH is the only guard** — `src/lib/kit/safe-git.js:153` (security): protocol.\<name\>.allow takes precedence over protocol.allow, so a repo that sets \`extensions.partialClone=origin\`, \`remote.origin.promisor=true\`, \`remote.origin.url=ext::sh -c touch% M\` and \`protocol.ext.allow=always\` gets a command run on any lookup of a missing object (for example \`cat-file -t \<unknown sha\>\`). With the wrapper's env minus GIT\_NO\_LAZY\_FETCH, git 2.43 created the marker. GIT\_NO\_LAZY\_FETCH only exists in git builds that include the 2024 CVE fix (2.45.1 and the backports), so on older git the transport override does not hold. — fix: Also override protocol.\<name\>.allow=never for ext/file/ssh/http(s)/git and for every protocol.\*.allow key found in the repo config, and set remote.\<n\>.promisor=false / remote.\<n\>.url= for each remote, or refuse when extensions.partialClone is set.

## Low (1)

- **Override cache fingerprint ignores included config files** — `src/lib/kit/safe-git.js:157` (security): fingerprint() stats only config, config.worktree and info/attributes of the git and common dirs. A filter driver or core.attributesFile added through an include.path / includeIf file (for example a work-tree file) after the first call reuses the stale overrides for the rest of the process, so the new driver is not switched off. The header comment says overrides are 'keyed by the stat of its config' and names only .gitattributes as needing fresh:true. — fix: Fingerprint every file from \`git config --list --show-origin --includes\`, or skip the cache when the config uses include.\*/includeIf.\*; document it.
