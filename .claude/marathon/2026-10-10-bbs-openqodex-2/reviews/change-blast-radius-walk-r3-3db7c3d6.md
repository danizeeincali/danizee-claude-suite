- **buildOldSide treats every cat-file failure as 'file not in base', silently dropping removed-symbol checks in partial clones** — `src/lib/kit/impact.js:312` (correctness): buildOldSide runs \`git cat-file blob \<base\>:\<path\>\` and on any non-zero exit does \`continue\` with the comment 'not in base'. safe-git sets GIT\_NO\_LAZY\_FETCH=1 and drops extensions.partialclone, so in a blobless partial clone (git clone --filter=blob:none, common in CI) the base blob is simply missing and cat-file fails even though the file exists at base. The file then disappears without a trace: it is not added to old\_not\_read, partial stays false, and risk.lower\_bound stays false. Reproduced: origin repo with util.js { helper, legacy } and main.js calling both; commit 2 removes legacy. In a fresh --filter=blob:none clone, \`impact --diff \<that diff\> --base HEAD~1 --json\` returns removed: \[\], removed\_with\_live\_callers: \[\], risk level 'low', partial false, lower\_bound false. The same command in the full clone returns legacy in removed\_with\_live\_callers with level 'high'. A removal that is still called, which the tool's own docs call 'high by itself', is reported as low with no caveat. The same line appears in .claude/helpers/kit/impact.js:312. — fix: Tell 'absent at base' apart from 'present but unreadable'. For example, check the path with \`git ls-tree \<base\> -- \<path\>\` or \`cat-file -t\`: if the tree has the entry but the blob read fails, push { file, reason: 'missing\_object' } (or 'git\_error') to not\_read so that partial and lower\_bound become true. - **Review step reports a failed git diff as 'no change to map'** — `.claude/commands/.shortcuts/w-review.md:109` (process): The new snippet (line 106) builds the diff with \`{ git diff ... "$BASE"; ...; true; } \> "$D"\`. The trailing \`true\` hides the exit status of git diff, and impact exits 0 on an empty diff. Line 109 then tells the reviewer to report that as 'no change to map', not as a failure. On a degraded network in a partial clone, git diff has to lazy-fetch the base blobs. When that fetch fails, git diff prints 'could not fetch ... from promisor remote' and writes nothing. Reproduced: in a --filter=blob:none clone whose remote is unreachable, the exact snippet produced a 0-byte diff and impact returned RC=0, touched \[\], risk low, lower\_bound false, and the note 'the diff names no files'. The blast-radius step therefore records a real change as having no impact. The lenses step guards against this case because it exits 1 on an empty diff. This step does not. The same text is in src/plugins/dot-shortcuts.js:2144-2147. — fix: Keep git diff's own status, e.g. \`git diff ... "$BASE" \> "$D" || { echo 'git diff failed' \>&2; rm -f "$D"; false; }\` before appending untracked files. Alternatively, have the instruction cross-check an empty result against \`git diff --quiet "$BASE"\` / \`git status --porcelain\` before reporting 'no change to map'.
