# Review c44b18aa-f63c-4098-852d-473fe69beaa7 — hardened-git-read-on-untrusted-repo, round 3

- Commit: a3ef179
- Angle: older environments and degraded networks
- Result: over tolerance
- 5 findings

## High (1)

- **Shadow copy has no size cap: a sparse packed-refs/index/shallow/sharedindex fills /tmp** — `src/lib/kit/safe-git.js:420` (security): buildShadow copies packed-refs, shallow, ORIG\_HEAD.., index and every sharedindex.\* with fs.copyFile and no size limit (only lstat isFile is checked). A file made with \`truncate -s\` takes no disk in the untrusted repo (e.g. unpacked from a tarball) but is written out in full to os.tmpdir(). Traced: r6/.git/index = \`truncate -s 2G\` (4 KB on disk); \`node .claude/helpers/kit/cli.js safe-git --dir r6 -- rev-parse HEAD\` wrote 2049 MB into /tmp/safe-git-shadow-\*/ before answering (exit 0). With packed-refs at 3G sparse: 3073 MB written, 11.6 s, while plain \`git rev-parse HEAD\` just reads it and fails in 2.6 s without writing. A \`truncate -s 1T\` file fills the shared /tmp/root disk (ENOSPC for every other process) on every call, including plain rev-parse HEAD. — fix: Cap each copied file (packed-refs/shallow/pseudo refs by a sane limit, index/sharedindex by e.g. a few hundred MB or by comparing st.blocks\*512 to st.size) and refuse (KitExit 2) above it; copy with a bounded stream that stops at the cap instead of copyFile.

## Medium (2)

- **refs/ symlinked to an outside folder is copied eagerly and recursively** — `src/lib/kit/safe-git.js:456` (security): copyTree skips symlinks only BELOW the top: fs.readdir(commonDir/refs) follows a refs symlink (and looksLikeGitDir's stat accepts it), so the whole target tree is copied into the shadow on every call. Traced: r1/.git/refs -\> outside/ made a file outside the repo appear as refs/heads/SECRET\_from\_outside in safe-git for-each-ref and copied a 200 MB file for rev-parse HEAD; r2/.git/refs -\> /usr made \`safe-git rev-parse HEAD\` run 132 s and copy \>2.5 GB of /usr into /tmp (plain git answers in 2 ms because it never walks refs/ for that). Same for a linked worktree's gitDir/refs (line 457). refs -\> / or $HOME reads every readable file of the user into /tmp and can exhaust disk. — fix: lstat commonDir/refs (and gitDir/refs) and refuse or skip it when it is not a real directory; also bound the total bytes/entries copyTree will copy.
- **Every call refuses on an ordinary JS checkout: .gitattributes walk counts ignored node\_modules** — `src/lib/kit/safe-git.js:314` (correctness): attributeFiles walks the whole work tree (ignored folders included, only '.git' skipped) and throws KitExit 2 past MAX\_DIRS=20000, before any git command runs. Traced: repo with node\_modules in .gitignore and 21211 folders under it -\> \`safeGit(r3, \['rev-parse','HEAD'\])\` fails 'more than 20000 folders ... cannot all be checked'. Installed node\_modules / vendor / build trees routinely exceed 20000 folders, so even rev-parse HEAD is refused there, and the walk also re-runs (seconds of I/O) on every call. — fix: Do not walk ignored or untracked folders: take attribute file paths from the index (\`ls-files -z -- '\*.gitattributes' .gitattributes\` via the shadow) plus info/attributes, or skip folders git would not read attributes from; keep a cap only for tracked folders.

## Low (2)

- **core.fsmonitor=false runs a program named 'false' on git 2.16-2.35** — `src/lib/kit/safe-git.js:331` (security): Before git 2.36 core.fsmonitor is a hook PATH, not a boolean: git\_config\_get\_fsmonitor only treats an EMPTY value as off, so \`-c core.fsmonitor=false\` makes status/diff run \`sh -c 'false ...'\` as the fsmonitor hook on every call (PATH-resolved, run from the work tree). Results stay correct (hook fails, full scan), but the wrapper itself spawns a program on older git, contrary to its no-program claim. — fix: Use \`core.fsmonitor=\` (empty): off on old git, and parsed as false by git \>= 2.36's maybe-bool.
- **'no system or global config' is untrue on git \< 2.32** — `src/lib/kit/safe-git.js:94` (facts): GIT\_CONFIG\_GLOBAL was added in git 2.32; older git ignores it and reads ~/.gitconfig and $XDG\_CONFIG\_HOME/git/config in every shadow run, while the header (line 28) states no global config is read. The user's own config is trusted so no exploit is traced, but the stated isolation and the tests' assumptions do not hold on older git. — fix: Also point HOME and XDG\_CONFIG\_HOME at the empty scratch folder for the git runs, or state the git \>= 2.32 requirement in the header.
