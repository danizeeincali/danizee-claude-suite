## Medium (3)

- **--incomplete overrides a fail verdict and any threshold** — `src/lib/kit/push-gate.js:73` (correctness): decide() returns abstain for any receipt marked incomplete before it looks at the verdict or counts. Reproduced: \`receipt --verdict fail --high 3 --threshold high --incomplete\`, then \`check --threshold high\`, gives decision abstain. A review that already found blocking issues stops blocking as soon as one category was skipped, and the w-review closing step tells the agent to add --incomplete in exactly that case. The same code is in .claude/helpers/kit/push-gate.js:73. — fix: Check failsThreshold() first and block on a fail verdict or findings at or above the threshold even when the receipt is incomplete; abstain on incomplete only when the recorded findings would not block.
- **Change id covers uncommitted edits, which a push does not send** — `src/lib/kit/push-gate.js:256` (correctness): The id hashes HEAD's tree plus the uncommitted diff and the untracked files. A review run over uncommitted fixes records a receipt for HEAD+fixes. If the developer then pushes without committing those fixes, check sees the same dirty id and abstains, even though the pushed commits (HEAD only) were never reviewed in that form. That is a wrong pass for the input the gate exists to judge. Same code at .claude/helpers/kit/push-gate.js:256. — fix: For check, key on what is pushed (base + HEAD tree) and treat a dirty tree as unreviewed, or have check refuse to abstain while the tree is dirty.
- **Documented receipt command never sets --threshold, so a threshold check always denies** — `.claude/commands/.shortcuts/w-review.md:222` (correctness): The closing step records receipts without --threshold, so every receipt is stored under 'none'. decide() blocks whenever the receipt's threshold differs from the check's (push-gate.js:274), so \`check --threshold high|medium|low\` denies even a 0/0/0 pass. Its message says to run /w-review again, and that writes the same 'none' receipt, so the user can never clear it. The threshold feature cannot be used through the workflow that is meant to feed it. The same text is in src/plugins/dot-shortcuts.js:2260. — fix: Add \`\[--threshold \<level\>\]\` to the closing-step command and say the check must use the same level. Or store counts without a threshold and judge them against the threshold given at check time.
