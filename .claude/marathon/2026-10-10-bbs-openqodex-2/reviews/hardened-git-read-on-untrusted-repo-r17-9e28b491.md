## Medium (3)

- **copyTree skips a refs/ folder it cannot list, so a loose ref in it silently resolves to a stale packed-refs value** — `src/lib/kit/safe-git.js:778` (correctness): copyTree does \`try { ents = await fs.readdir(s0, ...) } catch { return; }\`. Round 16 made the objects/ walk fail closed on an unlistable folder, but the refs walk still fails open. Git opens loose refs by name, which a write+exec-only folder (0333/0311) allows. Reproduced as user nobody: a repo whose packed-refs has main=095aecf and whose loose refs/heads/main=3600c39, with refs/heads at mode 0333. Plain \`git rev-parse HEAD\` and \`git log\` give 3600c39 ('two'). safe-git gives 095aecf with code 0, and \`log --oneline\` shows only 'one'. That is a wrong answer with no error, not a refusal. An unreadable ref FILE gives an error (copyCapped rethrows EACCES), so only folders are affected. .claude/helpers/kit/safe-git.js is identical. — fix: Handle readdir errors in copyTree as checkObjectsNotLinked does: return on ENOENT/ENOTDIR, otherwise refuse with KitExit 2 ('cannot list \<dir\>'). Add the 0333 refs/heads regression next to the round-16 one.
- **core.trustctime / core.checkStat are not carried into the shadow, so diff-files / diff-index report clean files as modified** — `src/lib/kit/safe-git.js:396` (correctness): allowedCore copies only bare/ignorecase/precomposeunicode/quotepath/filemode/symlinks/autocrlf/eol. Users set core.trustctime=false or core.checkStat=minimal on file systems whose ctime or inode numbers change on their own: SMB/NFS/FUSE mounts, Windows backup or AV tools, VM shared folders, and indexes written by JGit. Without these keys, every stat-dirty entry counts as changed in the plumbing commands that do not refresh. Reproduced: repo with core.trustctime=false, then \`chmod 600 a; chmod 644 a\`. Plain \`git diff-files --name-only\` and \`git diff-index --name-only HEAD\` print nothing. safe-git prints 'a' for both (code 0). A script asking \`diff-index --quiet HEAD\` 'is it dirty?' gets the wrong answer. status and diff refresh in memory, so they are unaffected. These keys only change stat comparison and cannot name a program. — fix: Add trustctime to CORE\_BOOL and checkstat: \['default','minimal'\] to CORE\_ENUM, validated like the others. Add a test with core.trustctime=false and a ctime-only change.
- **Network-path refusal for gitdir:/commondir misses mixed-separator UNC paths (/\host\share) on Windows** — `src/lib/kit/safe-git.js:628` (security): isNetworkPath only tests /^(\/\/|\\\\)/. On Windows, path.win32 treats '/' and '\\' alike, so a .git file holding \`gitdir: /\evil\share\r\` (or \`\/evil/share/r\`) passes the check. path.resolve then turns it into \\evil\share\r (checked: path.win32.resolve('C:\\work\\repo','/\\evil\\share\\r') === '\\\\evil\\share\\r'). looksLikeGitDir then lstats \\evil\share\r\HEAD, which opens an SMB connection to the attacker's host and sends the user's NTLM credentials. That happens before git runs and despite the header's 'network paths (//host, \\host) in a gitdir: file or commondir are refused'. Writing the .git file needs no symlink privilege, so an unpacked archive is enough. The same applies to commondir (line 325). The same check is also bypassed by a relative gitdir: naming a local symlink to a UNC target. — fix: Test the RESOLVED path instead of the raw text: on win32, refuse when path.win32.resolve(base, value) starts with '\\\\' (this covers \\?\UNC\ too). Optionally readlink the target chain before stat/realpath. Add a test for '/\\host\\share' with platform injected.

## Low (2)

- **limits.entries is checked only after readdir has loaded the whole folder, so one huge folder costs memory and time beyond the cap** — `src/lib/kit/safe-git.js:778` (performance): copyTree (line 778) and checkObjectsNotLinked (line 611) call fs.readdir, which builds a Dirent for every entry before the ++entries check runs. Measured: refs/heads/z with 1,000,000 empty files gives peak RSS 438 MB and 37.7 s before 'more than 100000 entries' is refused (the first 100k files are also copied one by one). Memory grows linearly, so about 10M entries (inodes only, no data) runs node out of heap despite the documented 100000-entry cap. None of this is bounded by --timeout. — fix: Iterate with \`for await (const e of await fs.opendir(dir))\` so the cap stops the read early. Optionally count entries before copying any of them.
- **info/grafts is not copied, so history differs silently in repos that still use grafts, and the header does not list it** — `src/lib/kit/safe-git.js:849` (correctness): Only info/exclude and info/attributes are copied from info/. Git (2.43 here) still honors $GIT\_DIR/info/grafts, with a deprecation hint. Reproduced: with grafts 'c3 c1', plain \`git log --oneline\` shows c3, c1. safe-git shows c3, c2, c1 with code 0. The header's 'Not reproduced' list (line 98) covers reflogs, core.worktree, and so on, but not grafts. Older repos stitched together with grafts get a different history and no warning. — fix: Copy info/grafts with copyCapped (it is data: commit ids only), or add grafts to the 'Not reproduced' list in the header.
