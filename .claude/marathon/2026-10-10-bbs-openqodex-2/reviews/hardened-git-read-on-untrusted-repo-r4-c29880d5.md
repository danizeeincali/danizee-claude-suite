## High (2)

- **git is spawned by bare name with cwd set to the untrusted repo, so a git binary inside the repo can run** — `src/lib/kit/safe-git.js:440` (security): defaultGitRunner calls spawnSync('git', ...) and passes no absolute path, and every shadow run (raw() in prepare) uses cwd: info.loc.real, which is the untrusted folder. On Windows, libuv's search\_path checks the child's cwd before PATH, so a git.exe committed at the repo root runs on every safe-git call. On POSIX the same happens when PATH has an empty or relative entry. I reproduced it on Linux: repo r1 with an executable ./git (\`touch PWN\_PATH; exec /usr/bin/git "$@"\`), then \`PATH=":$PATH" node .claude/helpers/kit/cli.js safe-git --dir r1 -- rev-parse HEAD\` created PWN\_PATH and still printed the right SHA. \`PATH=":$PATH" git -C r1 rev-parse HEAD\`, run from /, did not. A git clone keeps the executable bit, so bbs/fetch.js headOf(dest) goes through the same path on a fresh foreign clone. This is the one program-run guard the wrapper does not have. — fix: Resolve git to an absolute path once, from PATH entries that are absolute (skip empty, '.' and relative entries) and not inside the repo, and spawn that path. Alternatively run every git child with cwd = the private scratch folder and pass the repo location only through GIT\_DIR/GIT\_WORK\_TREE/-C. Add a test with an executable ./git and PATH=":$PATH".
- **Index copied verbatim: an entry named ../x makes diff/status read and print files outside the repo** — `src/lib/kit/safe-git.js:571` (security): The index is copied byte for byte into the shadow. Git does not run verify\_path on index entries when it reads the index from disk, so an entry whose name starts with ../ makes diff-files, diff and status lstat and read GIT\_WORK\_TREE/../\<path\>. Traced: in repo r2, I renamed the index entry \`zzzzzzzzzz/sec\` to \`../outside/sec\` (same length, SHA-1 trailer recomputed). \`node cli.js safe-git --dir r2 -- diff\` then exited 0 and printed \`+TOP SECRET KEY\`, the contents of outside/sec, a file outside the repository. \`status --porcelain\` listed \`AM ../outside/sec\`. A symlink-leading path is blocked by git, but \`..\` is not. bbs/fetch.js clones into a predictable folder below the user's project, so an attacker can choose a depth such as \`../../../../../.env\` that reaches the user's project secrets. The page header states that reads stay inside the repo and shadow. — fix: After building the shadow, run \`ls-files -z --cached\` (or \`--stage\`) on it before any work-tree command. Refuse with KitExit 2 when any entry is absolute or has an empty, '.', '..' or '.git' component (a case-insensitive check for '.git'). Add a regression test that patches an index entry to ../outside.

## Medium (1)

- **Untrusted include.path is followed to any path (outside the repo, FIFOs, UNC shares) though git never uses that config** — `src/lib/kit/safe-git.js:372` (security): inspect() reads the repo config with \`git config --file \<f\> --includes\`. Git therefore opens every include.path the hostile repo names, at any absolute path, even though the shadow never uses those values: only driver names are taken, and no driver can be defined because git never reads the repo config. Traced with a FIFO: \`include.path=\<outside\>/fifo\` and a writer blocked on the FIFO. The writer was released (marker OPENED created), which shows safe-git opened a path outside the repo. With no writer, \`safe-git --dir r5 -- rev-parse HEAD\` hangs for the full 60 s INTERNAL\_TIMEOUT on every call and then fails with \`cannot run git: spawnSync git ETIMEDOUT\`. On Windows the same key set to a \`//attacker-host/share/x\` UNC path makes the wrapper open an SMB connection with the user's NTLM credentials, which is egress to a host the attacker picks. Plain git would also do this, but reading the config through the shadow exists to avoid touching repo config at all. — fix: Read the config files with --no-includes. Included files can only add driver names, and the shadow never defines drivers, so nothing is lost. Alternatively, refuse when include.\*/includeIf.\* is present. Add a test with include.path pointing at a FIFO and check that it neither opens nor waits.
