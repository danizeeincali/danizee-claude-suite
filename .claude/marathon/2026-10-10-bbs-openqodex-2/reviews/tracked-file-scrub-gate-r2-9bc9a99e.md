## Medium (2)

- **push-gate check denies in unconfigured repos when safe-git refuses the repository** — `src/lib/kit/scrub.js:377` (correctness): scrubIfConfigured calls repoTop, which runs safeGit (rev-parse --show-toplevel), before it checks whether any pattern file exists. safeGit refuses repositories that plain git and push-gate's own changeId handle fine, for example a clone made with \`git clone --shared\` or \`--reference\` (objects/info/alternates), an unknown extension, or a refstorage other than files. scrubBlock (src/lib/kit/push-gate.js:237) catches the throw and returns deny with 'the scrub check is configured but could not run'. That reason is false because nothing is configured. Reproduced: in a \`git clone --shared\` repo with no .claude/kit at all, \`push-gate check\` returns {decision:'deny', exit:2, reason:'the scrub check is configured but could not run: .../objects/info/alternates borrows objects ...'}. The same check in the origin repo returns 'ask'. This breaks the documented promise 'with no pattern file nothing changes' and blocks pushes, even with a passing receipt, for users who never turned the scrub on. The scrubIfConfigured docstring also says it returns null when there is no work tree, but repoTop throws instead. — fix: Find the top with locateRepo (fs only) and check for the pattern files before any safeGit call. Return null when neither exists. Only then run the safeGit toplevel/scan path, so fail-closed applies only when the scrub is configured. Add a push-gate test with an alternates clone and no pattern file.
- **Gate scans only the HEAD tree; a secret committed and then removed in the pushed range passes** — `src/lib/kit/scrub.js:258` (security): The module says it scans 'the HEAD tree (what a push publishes)', and push-gate check relies on that. A push publishes every commit not already on the remote, not only HEAD's tree. Reproduced: pattern file .claude/kit/scrub-patterns.local = 'zebra-secret'. Commit a file containing zebra-secret, then commit its removal. \`push-gate check\` returns no scrub deny (decision 'ask' with no receipt; it would be 'abstain' with a passing receipt), so the secret is pushed in history. The w-review copy also says the check 'scrubs every tracked file ... and denies on any hit', which overstates what is enforced. — fix: In push-gate check, also scan the blobs introduced in base..HEAD (git rev-list --objects base..HEAD, or each commit's tree when there is no base/upstream). Otherwise correct the docs and w-review copy to say only the HEAD snapshot is checked and history is not.

## Low (1)

- **--max-file-bytes accepts values that HEAD mode can never honour** — `src/lib/kit/scrub.js:404` (correctness): parseArgs allows --max-file-bytes up to 2 GiB. In HEAD mode, however, a blob is read through safe-git's defaultGitRunner, which has a 256 MiB maxBuffer. Any tracked blob between 256 MiB and the cap aborts the whole scan instead of being listed in not\_scanned. Reproduced with a 300 MB committed file and --max-file-bytes 400000000: KitExit code 3 'git cat-file wrote more than 256 MiB of output'. That exit code also differs from the documented 'git failure is exit 1'. It still fails closed, but the result is a whole-scan error on input the CLI accepted. — fix: In HEAD mode, clamp cap to the runner's output limit minus header room, so larger blobs go to not\_scanned. Or reject --max-file-bytes above 256 MiB unless --worktree is given.
