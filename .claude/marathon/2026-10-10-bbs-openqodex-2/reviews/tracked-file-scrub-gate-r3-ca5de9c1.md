## Medium (2)

- **No-upstream push-gate check scans history the push will not publish** — `src/lib/kit/push-gate.js:244` (correctness): With no --base, change.base is the merge-base with @{upstream}. That is null for the first push of a new branch (no upstream yet), when the upstream ref is gone, or when you can't fetch to set one. scrubBlock then scans \`rev-list HEAD\`, which is all history, including commits the remote already has. Reproduced: a secret committed and then removed on main, main pushed to origin, a new branch 'feature' with one clean commit (\`git rev-list HEAD --not --remotes\` = 1 commit). push-gate check denies with a hit on file k:1 from the already-published commit. A pattern added to stop a rotated historical secret from coming back therefore blocks every new-branch push forever. On long-lived repos, the full-history scan also runs into the 2 GiB total, the 200000-pair cap, or the 60 s git timeout, each of which is a deny. — fix: When there is no base, scan \`rev-list HEAD --not --remotes\`, which is what a push publishes relative to the remote refs you already know and works offline. Fall back to all of HEAD's history only when the repo has no remote-tracking refs. Update the w-review/dot-shortcuts copy to match.
- **Timeout error tells the user to pass --timeout, which scrub and push-gate check reject** — `src/lib/kit/scrub.js:446` (correctness): Every scrub git call goes through safeGit with its 60000 ms default timeout, and neither scrub nor push-gate check can change it. When a call runs over (diff-tree --stdin over a long history, or a cat-file batch on a slow or network disk), safe-git throws 'git diff-tree took longer than ... ms and was stopped (raise it with --timeout \<ms\>)' with exit 3. Reproduced: scrub then rejects --timeout ('unknown flag --timeout'), and so does push-gate check. Exit 3 is also not among scrub's documented exits (0/1/2). On a slow environment the gate denies permanently and the advice it gives goes nowhere. — fix: Accept --timeout \<ms\> in scrub (and pass a timeout through scrubIfConfigured and push-gate check) and forward it to safeGit. Alternatively, catch the timeout KitExit in scanRepo and rewrite the message to name a working remedy (--base / --history \<base\>), and document exit 3.
