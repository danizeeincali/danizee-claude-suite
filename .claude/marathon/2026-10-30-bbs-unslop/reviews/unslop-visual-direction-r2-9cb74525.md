## Medium (2)

- **light field skips the banned-word check, so slop words reach the prompt with exit 0** — `src/lib/kit/visual-direction.js:198` (correctness): prompt refuses a sentence that has banned style words, but the optional light string is only checked for being a non-empty string and goes into the prompt as is. Probe: light 'stunning neon cyberpunk glow, 8k cinematic' gives exit 0 and a prompt containing 'light: stunning neon cyberpunk glow, 8k cinematic'. The power brief says to avoid glossy abstractions, and the module puts the sentence through the gate for exactly this reason, so the second free-text field undoes that gate. The same file copy is in .claude/helpers/kit/visual-direction.js. — fix: Run the same BANNED match (factor it out of checkSentence) on ctx.light, and exit 1 with 'light has style words that read as slop: ...' when it hits; add a test that a banned light is rejected.
- **Any sentence in a non-Latin script fails no-concrete-subject, so prompt always exits 1** — `src/lib/kit/visual-direction.js:122` (correctness): The concrete-subject check removes every character outside \[a-z0-9' -\] before counting content words, so a Japanese or Cyrillic sentence becomes empty. Probes: '陶芸家が朝の光の中で木の作業台で粘土の鉢を形作る' and 'Плотник строгает доску на верстаке в утреннем свете.' both return ok:false with no-concrete-subject, and prompt then refuses them. Accented Latin passes only because the stripped words still leave ASCII parts. The error tells the user to 'name a real thing', which they already did, so there is no way through except rewriting in English. — fix: Use Unicode classes (/\[^\p{L}\p{N}' -\]+/gu) for the content-word split, and for scripts without spaces skip the two-word count or count characters instead; add a non-Latin test.

## Low (3)

- **One-sentence check still flags quoted questions and abbreviations outside the short list** — `src/lib/kit/visual-direction.js:86` (correctness): After the r1 fix, some single sentences are still flagged not-one-sentence, and prompt then exits 1: 'A sign reading "Open?" hangs on a wooden door in morning sun.' ('?' or '!' is not given the lowercase-next rule), 'A flag of the U.S. Navy hangs on a wall' ('u.s' is not in ABBREV) and 'A brass kettle at No. 5 on a stove' (a number after the period). These sentences are rare in visual briefs and the message tells the user how to fix it, so this is low. — fix: Apply the lowercase-next skip to '?' and '!' when a closing quote follows, treat a token made of dotted single letters (u.s, u.k) as an abbreviation, and do not split when the next character is a digit.
- **No length cap on light and avoid entries, so the prompt can be megabytes** — `src/lib/kit/visual-direction.js:194` (performance): The sentence is capped at 30 words, but light and each avoid entry can fill the whole 8 MiB input. Probe: a 7,000,000-character light gives exit 0 and about 7 MB of prompt JSON. An image tool would reject that or cut it short, and the user gets no warning. — fix: Cap light at about 20 words and each avoid entry at about 40 characters (and the list at about 20 entries), and exit 1 with a clear message when over.
- **Unknown context keys are dropped without a message, so a typo changes the decision** — `src/lib/kit/visual-direction.js:137` (correctness): decide reads only the keys it knows. A misspelt key such as {screen:'dashboard', slots:'empty-state'} is dropped without a message and the answer is needed:false, kind 'none', where 'slot' would have given a visual. prompt drops misspelt keys the same way (for example headline-side or display\_wdith). Nothing tells the caller the field had no effect. — fix: Reject or warn on keys outside each subcommand's known set (for example an unknown\_keys list in the output, or exit 1).
