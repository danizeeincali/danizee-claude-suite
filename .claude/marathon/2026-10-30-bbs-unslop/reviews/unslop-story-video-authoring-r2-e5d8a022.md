## High (1)

- **Selector camera measures before images and fonts load, so the crop lands on the wrong region** — `src/lib/kit/story-plan.js:473` (correctness): cameraScript is an inline \<script\> at the end of \<body\>, so it runs at parse time, before images (and web fonts) have loaded. It measures getBoundingClientRect once and never measures again. Probe: a page with \<img src=big.png\> (600x300, no width/height attributes) above .card, with camera {selector:'.card'}. The script read the card top as about 18px, but after load it is at 304px. The page was cropped at 4x on empty space above the card on all 3 runs. The header says the selector is 'measured once at load', but it is measured before load. Pages with images above the part that changes are a normal input, so the camera frames the wrong area and nothing reports it. — fix: Run the measurement after the page has loaded: on window 'load' and after document.fonts.ready, or immediately if document.readyState is already 'complete'. That is still one measurement with no timers. Add a browser-probe test where an image without dimensions sits above the camera target.

## Medium (3)

- **Two selector strings that match one element override each other's animation lists** — `src/lib/kit/story-plan.js:442` (correctness): Animations are grouped by selector string (anims keyed by sel), and each group gets its own \`html.story-play :is(sel){animation:...}\` rule. When two different strings match the same element, the cascade keeps only one \`animation\` shorthand, and the other's tweens are dropped without warning. Probe: step a sets css h1 {color: blue}, step b swaps '.hero h1'. The h1 runs only story-w2, stays red through step a's tween, and the color change never happens. check() accepts this story and says nothing. — fix: Emit each animation from its own rule using animation-composition or separate longhand layers. Or, more simply, have check flag a swap/redline/css selector that differs from another step's selector but could match the same element, and document that one element must use one selector string across steps. A test should cover h1 plus '.hero h1'.
- **A swap or redline replaces the element's own ::before/::after from frame 0** — `src/lib/kit/story-plan.js:439` (correctness): The swap ::before rule and the redline ::after rule apply under html.story-play from load, not only inside the step's window. They set content and position:absolute with higher specificity than the page's own pseudo-element rules. Probe: the original page has .btn::before{content:'→ '} and a clearfix .row::after{content:'';display:table;clear:both}. At t=0 the icon reads 'Start', and the clearfix is gone: .row height drops from 100 to 0 and the next block moves from y=124 to y=16. This breaks the header's promise that 'no step rule touches layout before or outside its window', and the before frame no longer matches the original screen. — fix: Where the page CSS defines ::before/::after for a swap or redline selector, make emit refuse or note it. At minimum, document the limit and have check/emit report it. A browser-probe test with an existing ::after clearfix on a redlined element should assert the first frame is unchanged.
- **A later color step on a swapped element brings the old text back under the new text** — `src/lib/kit/story-plan.js:432` (correctness): The swap hides the old text with color:transparent inside the swap animation. Any later step's css animation on the same selector comes later in the animation list and wins for color. Probe: step a swaps .btn, then step b sets .btn {color:#fff}. At the end the element's color is rgb(255,255,255), so the old 'Go' is drawn again under the ::before 'Start free'. check accepts the story, and a palette step after a text swap is a natural ordering. — fix: Have check flag a color change on a swap selector in a step after the swap. Or emit the swap's transparency as the last animation in the list and carry the new ink through later color steps. Add a test for this ordering.

## Low (2)

- **check accepts a camera rect beyond the frame width, which renders blank** — `src/lib/kit/story-plan.js:135` (correctness): checkCamera allows x up to 20000. #story-page stays at frame width (1080 or 1920) with overflow:hidden, and cameraCss grows only its height. A rect with x at or beyond the frame width passes check and crops onto clipped, empty space. — fix: In checkCamera, require x + w to be at most the frame width (or widen #story-page to x + w in cameraCss).
- **Swap or redline on img/input is documented as unsupported but check accepts it** — `src/lib/kit/story-plan.js:198` (correctness): The header says swap and redline need a pseudo-element, so not img or input. check still accepts swap {selector:'img'} or redline {selector:'input'} without a problem, and the emitted video just blurs the element or shows no tag. — fix: Make check add a problem (or a note) when a swap or redline selector's last compound starts with img, input or another void element.
