## Medium (7)

- **emit --out can overwrite the --page (or --file) input** — `.claude/helpers/kit/story-plan.js:489` (correctness): run() writes --out without checking it against the inputs. \`story-plan emit --file s.json --page p.html --out p.html\` exits 0 and replaces the original screen with the story page. A second run then wraps the story page inside itself, and the original is gone. Reproduced. The peer verb fidelity refuses this case ('same file as ...; refusing to overwrite an input', by path and by dev/ino), so this breaks a kit convention as well as losing the user's source file. — fix: Resolve --out and refuse (exit 1) when it equals the --page or --file path, or names the same dev/ino (a hard link or symlink), as fidelity.js does. Add a test for --out == --page.
- **Redline/swap position:relative changes the 'before' layout from frame 0** — `.claude/helpers/kit/story-plan.js:328` (correctness): The rules \`html.story-play :is(sel){position:relative}\` (redline, line 328; swap, line 339) are not tied to any step window. They apply from t=0 and outrank the page's own rule, so an element the page positions absolute, fixed or sticky jumps out of place before any step runs. I rendered with story-render a page whose \`.btn{position:absolute;right:10px}\` is redlined and swapped in the template: the 'Go' button sits at the left in the first frame instead of the right. The spec says steps change values, never structure, and the first frame should be the original screen. — fix: Do not override position. Anchor the tag/overlay without changing layout (for example, apply position:relative only when the computed position is static, which CSS cannot express, so draw the redline with outline plus box-shadow or an outline-only treatment). At minimum, have check refuse or warn, and test that the first frame matches the original.
- **Swap overlay is pinned to the old text's width, so longer new text wraps and overflows** — `.claude/helpers/kit/story-plan.js:340` (correctness): The swapped text is an absolutely positioned ::after with width:100% of the element as it was before the swap. When the new text is longer than the old one, it wraps onto extra lines over the content below. The template's own story does this: 'Go' becomes 'Start free'. In the frames from story-render render, 'Start' and 'free' sit on two lines, spilling below the button. Text swaps are a core feature, and the shipped example renders broken. — fix: Give the overlay white-space:nowrap and width:max-content (or min-width:100%), so it keeps the old box's left edge without being bound to its width. Add an emit test (or a render probe) for a swap whose new text is longer than the old.
- **An unmatched '\<script'/'\<style' mention silently deletes the rest of the page** — `.claude/helpers/kit/story-plan.js:221` (correctness): stripElements and pullStyles scan raw text without knowing about comments or attributes. When a \`\<script\` (or \`\<iframe\`, \`\<object\`, \`\<style\`) appears inside a comment or an attribute value and no closing tag follows, everything after it is dropped (\`i = html.length\`). Reproduced: \`\<!-- analytics \<script\> removed --\>\<div class=card\>...\` emits a page whose body is only \`\<!-- analytics\`, an unclosed comment that also swallows the frame's closing tags and the credit. Likewise, \`\<div title="\<style\>"\>\` cuts the page at that point. emit still exits 0, so the user gets a blank video. — fix: Skip \`\<!-- ... --\>\` comments and quoted attribute values when scanning. If a close tag is missing, drop only the open tag rather than the rest of the document. Add tests for a comment that mentions \<script\> and for an attribute that contains \<style\>.
- **Scoping html/:root rules to #story-page breaks rem sizing** — `.claude/helpers/kit/story-plan.js:254` (correctness): scopeCss rewrites \`html{font-size:62.5%}\` (or \`:root{font-size:...}\`) to \`#story-page{...}\`. rem units still resolve against the real \<html\> element of the story page, which stays at 16px, so every rem-sized length on a page that sets its root font size renders larger than in the original. The 'before' frame then no longer matches the screen being redesigned. — fix: Lift root font-size declarations from html/:root rules onto the story document's real html element (or keep html/:root rules unscoped except for background and overflow). Add an emit test with html{font-size:62.5%}.
- **Credit is optional, but the spec says every video carries one** — `.claude/helpers/kit/story-plan.js:361` (facts): The power brief says 'Every video carries a small credit to the author.' In story-plan, credit is optional: check never reports a missing credit, and emit leaves out #story-credit when credit is absent (line 361; the wide-format test even emits with credit: undefined). A story with no credit passes check --strict and renders a video with no credit at all. — fix: Make credit required (a 'credit-missing' problem in check, documented in the header) or emit a default credit line when none is given. Add a test that a story with no credit is not ok (or still carries a credit).
- **No camera crop onto the part that changes most** — `.claude/helpers/kit/story-plan.js:365` (facts): The spec asks for a square or wide frame 'cropped close on the part that changes most'. emit always places the whole page at 0,0 in the frame at 1:1 scale (#story-page left:0; top:0). There is no story field for a focus selector or region and no zoom or translate. On a normal page the redesigned part can fall outside the 1080x1080 frame, or fill only a corner of it. No test covers framing. — fix: Add an optional camera field (for example { selector | x, y, w, h }) that check validates and emit applies as a transform on #story-page. Default it to the union of the touched selectors, or document the gap. Add a test.

## Low (2)

- **Wide stories render as a square crop unless --format wide is repeated** — `.claude/helpers/kit/story-plan.js:375` (correctness): The emitted page states its format only through the viewport meta width. story-render reads only story-duration-ms and defaults to square, so \`story-render render --file wide-story.html\` silently crops a 1920x1080 story to 1080x1080. The seam between the two verbs carries the duration but not the frame size. — fix: Emit a machine-readable format marker (for example \<meta name="story-format" content="wide"\>) and ask the renderer stream to read it, or have emit's result say to pass --format wide.
- **emit result shape in header omits \`stripped\`** — `.claude/helpers/kit/story-plan.js:9` (docs): The header documents emit as returning { html, duration\_ms, steps } or, with --out, { out, bytes, duration\_ms, steps }. Both forms also return a \`stripped: { scripts, links }\` field (lines 396 and 491). — fix: Add \`stripped\` to both result shapes in the header comment.
