## Medium (2)

- **A markdown doc whose code sample contains className= is sniffed as jsx, and its prose is never scanned** — `src/lib/kit/slop-audit.js:617` (correctness): sniff tests the jsx signals (\`\bclassName\s\*=\`, \`function Foo(\`, \`=\> (\<\`) anywhere in the text, before the markdown check. So a README or docs page for a React component, a normal input for this verb, gets sniffed as jsx when a fenced example contains className=. jsxVisible then treats the prose as code and blanks it, and the markdown fence masking never runs. Probe: '# My Button\n\nWelcome back! This is a revolutionary button.\n\n\`\`\`jsx\n\<Button className="px-4"\>Click me!\</Button\>\n\`\`\`' via --file README.md gives format jsx and 0 hits. With --format md the same file gives greeting-headline, exclamation-marks and hype-words on line 3. The scan passes silently under --strict. This is the same class of bug as the r1 README-as-html sniff, which was fixed only for a leading HTML block. — fix: Run the markdown signals before the jsx signals when the text does not start with import/export, or test the jsx signals on the text with fenced blocks and inline code removed. Add a test for a README with a \`\`\`jsx fence containing className=.
- **A TSX generic arrow \<T extends X\>(...) is parsed as a JSX element, so the code after it is read as copy** — `src/lib/kit/slop-audit.js:246` (correctness): tagStartsAt accepts '\<' after '=', and parseElement accepts \`\<T extends unknown\>\` as an element named T with two boolean attributes. Everything after the '\>' is then shown as text children up to the next '\<' or '{', so top-level code reaches the copy detectors. \`\<T extends ...\>\` is the usual way to write a generic arrow in a .tsx file. Probe: g.tsx with \`const identity = \<T extends unknown\>(x: T): T =\> x;\` followed by \`const port = 1234;\` and \`throw new Error('year is required!');\` gives fake-data on line 3 and exclamation-marks on line 4, and --strict would exit 2. The r1 regression tests cover useState\<string\> and forwardRef\<...\> but not this form. — fix: In tagStartsAt or parseElement, reject a candidate when the name is followed by \`extends\` and the closing '\>' is followed by '(' (a type-parameter list). Add this case to the TS-generics regression test.

## Low (2)

- **jsx scanner has no regex-literal handling, so a backtick in a regex swallows the rest of the file** — `src/lib/kit/slop-audit.js:321` (correctness): scanCode treats every quote as the start of a string. A regex literal holding a backtick, such as \`const re = /\`/;\`, opens a template string in skipString that runs to the end of the file. Nothing after it is read: \`\<h1\>Welcome back!\</h1\>\` on the next line gives 0 hits, a silent false negative. A regex holding '{' or '}' inside a {expression} also shifts the brace depth. This is rare in component files. — fix: In scanCode, when '/' follows an operator, '(', ',', '=', ':', '\[', '!', '&', '|', '?', '{', '}', ';' or a line start, skip a regex literal (with escapes and \[...\] classes) before checking for quotes.

The unit and packaged tests check oversize input only through stdin.
