## Medium (1)

- **Shadow DOM content (web components, declarative shadow roots) is silently missing from the copy** — `src/lib/kit/page-snapshot.js:646` (correctness): snapshotDom copies doc.documentElement.cloneNode(true) and serialises clone.outerHTML. Neither clones nor serialises shadow roots, so whatever a custom element renders in its shadow tree is not in page.html. Probe (file:// page, real Chromium): \<my-card\> attaches an open shadow root holding \<button aria-label="Shadow button"\>Shadow text\</button\>. The screenshot shows the button. page.html contains only \<my-card\>\</my-card\>, and nothing in skipped, the header or the \`next\` text says content was lost. On a Lit/Stencil/Shoelace-style site most of the visible text and its accessible names and roles end up in shadow trees, so the 'baseline copy' is largely empty while the run reports captured:true with nothing skipped. The header says 'the rendered document is copied' and names only scripted or canvas backgrounds as not surviving. — fix: In snapshotDom, serialise open shadow roots with el.getHTML({serializableShadowRoots:false, shadowRoots:\[...\]}) (Chromium 125+), or walk the original tree and emit each open shadowRoot as \<template shadowrootmode="open"\>, cleaned the same way. Note closed or unreachable roots in skipped, and name the limit in the header and the \`next\` text. Add a probe test with an open shadow root.

## Low (2)

- **\<object\> is removed together with its fallback content, losing rendered text and alt** — `src/lib/kit/page-snapshot.js:706` (accessibility): The DOM pass (DROP at line 706) and the text pass (EMBEDDING at line 523) remove \<object\> with all its children. HTML's fallback content inside \<object\> (an \<img alt\>, text) is the accessible alternative, and it is what the live page draws when the object's data fails to load. Probe: \<object data="nope.svg"\>\<img alt="Fallback chart" src="data:..."\>Fallback text\</object\> renders the fallback in the screenshot, but page.html has neither the img nor its alt nor the text. The copy can never load the object (CSP default-src 'none'), so the fallback is exactly what should stay. — fix: For object, replace the element with its (already cleaned) child nodes instead of removing them, and keep listing the data URL in skipped. embed and applet have no fallback, so removing them stays correct.
- **Skipped reason 'linked instead' now promises a stylesheet the copy's CSP never loads** — `src/lib/kit/page-snapshot.js:587` (docs): resolvePending keeps an unread pending sheet (for example a cross-origin sheet whose body was late) as \<link rel=stylesheet href=absolute\> with reason PENDING\_UNREAD 'stylesheet could not be read; linked instead'. Since round 5, page.html carries CSP default-src 'none' with style-src 'unsafe-inline' data:, so that link is blocked when the copy is opened and the copy shows unstyled. Read in manifest.json, the reason suggests the styles still apply through the link. The header says absolute assets are not loaded, but this per-entry reason contradicts it. — fix: Reword PENDING\_UNREAD to something like 'stylesheet could not be read; left as a link the copy does not load', or drop the link and say so, and update the test that checks the string.
