## Medium (3)

- **Reduced motion still plays the swap's blur-out and fade on the swapped element** — `src/lib/kit/story-plan.js:630` (accessibility): Under prefers-reduced-motion a swap's only reduced rule is for the inserted \<story-swap\> (opacity 1, animation none). The swapped element keeps its story-wN animation from the shared stack (no reduced rule sets animation:none on swap.selector unless that selector also has a css step or redline). Probe: story with a swap on .btn only, Chromium reducedMotion 'reduce', at t=2300ms (mid-tween) .btn has filter blur(8px) and opacity 0, and the new text, a child of it, blurs and fades with it. That contradicts the header line 104 claim 'Under prefers-reduced-motion the final state is shown', and it puts the blur motion back in front of viewers who asked for less motion. The test named 'swap uses blur-out and blur-in, with reduced-motion final state' (test line 313) checks only the keyframe text, and the browser reduced-motion test (line 791) uses a selector that also has a css step, whose reduced animation:none hides the bug. — fix: In the swap branch, push \`html.story-play :is(${w.selector}){animation:none !important}\` (or animation-name:none) into \`reduced\`; the stack's reduced rule already holds the old text transparent. Add a browser assertion with reducedMotion 'reduce' on a swap-only selector: filter none and opacity 1 at mid-tween.
- **The page's lang and dir are dropped: an RTL page renders LTR and every page is labelled lang="en"** — `src/lib/kit/story-plan.js:743` (accessibility): scanPage drops the \<html\> tag with all its attributes (lines 369/373), preparePage keeps only class and style from \<body\> (line 551), and emit hard-codes \<html lang="en"\>. Probe: \<html lang="ar" dir="rtl"\> with an Arabic h1 gives computed direction 'ltr' and documentElement.lang 'en' in the emitted page. An Arabic or Hebrew page comes out mirrored wrong, so frame 0 no longer matches the original; :lang() rules, CJK glyph choice and hyphenation change too, and assistive tech reading the page gets the wrong language. — fix: Carry lang and dir from the original \<html\> (and dir/lang from \<body\>) onto the emitted \<html\> (or #story-page/#story-body), escaped, falling back to lang="en" only when the page has none; add a test with dir="rtl".
- **on\* handlers survive after a '--!\>' comment end and inside svg \<title\>/\<textarea\>** — `src/lib/kit/story-plan.js:486` (security): The header promises on\* handlers removed. Three cases still produce live handlers in the emitted page (Chromium probe, each onerror ran): (1) \`\<!-- x --!\>\<img src=x onerror=...\> --\>\`: a browser ends the comment at '--!\>', but scanPage and cleanTags (line 486) look only for '--\>', so the img is treated as comment text and kept as is; (2) \`\<svg\>\<title\>\<img src=x onerror=...\>\</title\>\</svg\>\` and (3) \`\<svg\>\<textarea\>\<img ... onerror=...\>\</textarea\>\</svg\>\`: RAWTEXT/RCDATA (line 316) treat title and textarea as raw text everywhere, but inside svg (foreign content) they are not, so the markup inside is parsed and its handler runs. The same reading also skips a \<script\> placed there in scanPage. Graded medium, not high: the page is the author's own and story-render blocks non-local hosts, but the stated stripping is not what happens. — fix: End comments at the first of '--\>', '--!\>' (and '\<!--\>'/'\<!---\>') in both scanners; skip title/textarea as raw text only outside \<svg\>/\<math\> (track a foreign-content depth), or drop the raw-text skip and over-strip instead. Add each of the three cases to the stripping tests.

## Low (1)

- **Swap text defaults to #111 whatever the element's own text colour** — `src/lib/kit/story-plan.js:624` (accessibility): With no swap.ink, the new text is #111 even when the element's text is light. The template swaps .btn with no ink. Probe: a button with white text on #1d4ed8 shows the new label in #111 at about 2.8:1 contrast, below the 4.5:1 AA level, and the original label was 6.7:1. The swap-ink note fires only when a step changes color on the swap selector, so a check gives no warning here. The browser test at test line 791 asserts ink rgb(17,17,17) on a final background of rgb(0,0,0), which is unreadable text written into a passing test. — fix: When ink is not given, have the marks script copy the element's computed color at t=0 (inside z(place)) onto the \<story-swap\>. Or add a check note that names the default ink whenever a swap has no ink.
