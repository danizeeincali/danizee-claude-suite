## Medium (3)

- **render drops frame-capture's blocked\_origins, so remote fonts/images vanish from the MP4 without notice** — `src/lib/kit/story-render.js:252` (correctness): capture() returns blocked\_origins (frame-capture.js:296), but render() builds its result from p and bytes only and throws that list away. The power brief says a story's remote fonts/resources are the known gap. Here they are now blocked, which is correct, but the user is not told. Probe: a file:// story that links fonts.googleapis.com rendered with exit 0 and the result {out, frames:5, ...} had no mention of the blocked origin, so the video quietly used a fallback font. — fix: Copy cap.blocked\_origins into the render result (and document it in the header). A non-empty list could also add a short warning field.
- **packaged test name promises a render, but no branch renders and the else branch asserts nothing** — `test/kit-unslop-story-video-renderer-packaged.test.js:49` (test-quality): The test is titled 'renders when playwright resolves', but the packaged check never reaches capture, encode or rename. With NODE\_PATH cleared it takes the exit-4 'playwright not installed' branch (confirmed: no diagnostic was emitted). The fake ffmpeg is only ever probed with -version and never encodes. If playwright did resolve, the else branch accepts any outcome (crash, exit 1, partial o.mp4) and only checks egress. The packaged\_ finish line is therefore honest only for plan, play, refusals and the two exit-4 stops. Its title implies more. The real render success path is proven only by the unit e2e test, which t.skip()s silently wherever playwright cannot be resolved. — fix: Rename the packaged test to what it proves (no render). In the else branch assert a definite outcome (e.g. code 4 with the 'browser could not start' or egress-blocked reason, nothing written) instead of only a diagnostic. Record that the render success path is covered by the unit e2e test, and do not let it skip silently in the tests\_green run.
- **test named 'a failing ffmpeg exits 1' tests a browser-launch failure; the encode-failure path has no test** — `test/kit-unslop-story-video-renderer.test.js:190` (test-quality): The test's fake playwright throws on launch, so it asserts exit 4 / 'browser could not start'. The header documents 'A failed encode exits 1 with the tail of ffmpeg's stderr' and the .part.mp4 cleanup (story-render.js:249,256), and neither has a test. A manual probe with an ffmpeg stand-in that passes -version and then exits 3 did give exit 1 with the stderr tail, so the code works. A regression there would go unnoticed. — fix: Add a test with a fake playwright that captures frames (or a stub capture) and io.exec that succeeds for -version and returns {code:1, stderr:'x'} for the encode. Assert KitExit code 1, the stderr tail in the message, no out file, no .part file and no temp frames dir. Rename the current test to say it covers browser launch failure.

## Low (4)

- **duration scanner diverges from HTML tokenising (quotes in unquoted values, RCDATA/template content)** — `src/lib/kit/story-render.js:78` (correctness): readTag treats any ' or " inside a tag as opening a quote. A page with \<meta name=description content=it's\> followed by the real \<meta name="story-duration-ms" content="3000"\> and a later apostrophe is refused with 'no story duration' (probed). Line 93 also skips only script/style, so a \<meta name=story-duration-ms\> inside \<textarea\>, \<title\> or \<template\> wins over the real declaration (probed: textarea meta 5 beat body attribute 2000). — fix: Open a quote only right after '=' (with optional whitespace), as the HTML tokenizer does. Add textarea, title, template and noscript to the raw-text skip list.
- **--keep-frames with a failed encode leaves the temp frames dir but the error never names it** — `src/lib/kit/story-render.js:249` (correctness): When ffmpeg fails, render throws KitExit 1 and the finally block keeps framesDir under --keep-frames. The message carries no frames\_dir path, so the kept /tmp/story-render-XXXX directory is orphaned (probed: it stayed behind after exit 1). — fix: Include framesDir in the ffmpeg-failed message when keepFrames is set, or remove the directory on failure.
- **at-cap render assertion passes on any non-throwing result** — `test/kit-unslop-story-video-renderer.test.js:185` (test-quality): code() returns 0 for any resolved value, so this line passes on the {exit:4, reason:'playwright not installed'} return. It shows only that a 1000 ms story is not refused at --max-seconds 1. The test title also lists 'over-cap' next to this line, which reads as if this line checked it. — fix: Await the result and assert r.exit === 4 and the playwright reason (proving validation passed and capture was reached).
- **header overstates isolation: 'only the file:// URL of the story is ever loaded'** — `src/lib/kit/story-render.js:19` (docs): frame-capture allows every local URL. The story's other file:// subresources (any readable file the page references) and http://localhost / 127.0.0.1 requests all load. Only non-local egress is blocked. — fix: Reword to: 'the story is loaded from its file:// URL; only local (file://, localhost) requests are allowed, everything else is blocked in the browser'.
