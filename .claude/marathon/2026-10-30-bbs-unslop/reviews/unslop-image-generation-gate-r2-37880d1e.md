In questionOf, put model, size, service and cost before the prompt and quote the prompt safely (JSON.stringify, or a fenced block with the newlines shown as \n). Add a test where a prompt holding a fake 'Model: ... Size: ...' cannot appear before the real values in question.
- **check never uses up the approval, so one yes covers any number of paid runs until the step chooses to call used** — `src/lib/kit/image-gate.js:297` (correctness): check is read-only and lock-free, and it exits 0 every time while the record is 'approved'. Probe: request, approve, then check three times: exit 0, 0, 0. 'One approval covers one run' (header lines 39-41) holds only if the agent remembers to call \`used\` after each run. A step that crashes after the tool call, is retried, loops, or runs twice in parallel passes check again and pays again with no new yes. In the other direction there is no failure path: if the image tool errors or times out, the step either calls \`used\` (then that exact request can never be retried; request returns reroll and tells the step to change the prompt) or skips it (then the approval stays open for any number of further runs). No test covers check twice, or two concurrent checks, before \`used\`. — fix: Make the pass consume the approval: under withStateLock, have check (or a \`check --claim\`) move approved to an in-flight or used state and exit 0 only for the caller that made the move. Add a separate \`failed --id\` that sets a claimed record back to approved (or a 'retry' state the user can see) for a tool error. Test that a second check after a claimed pass exits 2, and that only one of two parallel claims exits 0.
