## Medium (2)

- **Halftone turns transparent pixels into solid ink** — `.claude/helpers/kit/image-effects.js:175` (correctness): lum() multiplies luminance by alpha, so a fully transparent pixel reads as black. That suits glyph and dither, where dark is the background. Halftone draws dots where the picture is darker, so it fills every transparent area with full-size palette\[0\] dots. Rendered in Chromium with a 400x200 PNG (a white disc on a transparent background) and --palette #0b1020,#f5f0e0: the whole transparent area became a solid #0b1020 block around a light disc. A transparent-background hero (a logo, product cutout or illustration) comes out as an inverted dark rectangle. — fix: For halftone, composite transparent pixels onto the paper colour (for example use lum\*a + (1-a)\*lum(P\[1\]), or fill the sample canvas with P\[1\] before drawImage) so transparent areas get no dots; add a rendering or unit test with an alpha pixel.
- **Glyph grid leaves out the cell animation the spec names** — `.claude/helpers/kit/image-effects.js:21` (correctness): The power brief's idea for the glyph treatment says 'only a small share of cells change at eight to twelve steps per second, paused off screen'. The module says it has 'no animation loop', and the test (canvas kinds, 'no animation loop') enforces that there is no requestAnimationFrame/setInterval/setTimeout. So the glyph kind is a static render, and nothing records a decision to drop this behaviour against the brief. — fix: Add an opt-in, throttled (8-12 Hz) partial-cell redraw from the existing atlas, paused by an IntersectionObserver and switched off under prefers-reduced-motion, with a test. Or, if dropping the animation is deliberate, record that as a change to the brief and say so in list/notes.

## Low (4)

- **--palette means a different thing for each kind; halftone silently drops the third color** — `.claude/helpers/kit/image-effects.js:162` (correctness): Dither and glyph sort the palette dark to light. Duotone and halftone use the order given. So the same --palette '#f5c542,#0b1020' gives a normal image with glyph or dither, a negative-looking duotone (the brief says brightness maps onto 'the darkest surface and the accent'), and light dots on dark paper with halftone. Halftone also accepts three colors but uses only P\[0\] and P\[1\], with no error or note. Probe: emit --kind halftone --palette '#000,#888,#fff' returns exit 0 and its notes never mention the dropped color. — fix: Reject a third color for halftone (or add a note when it is ignored). Add a note when the duotone or halftone order runs light to dark, or say plainly in list/usage which kinds sort the colors.
- **Dither canvas aspect drifts from the image because the grid is rounded** — `.claude/helpers/kit/image-effects.js:197` (correctness): The dither canvas is cols x rows, with each value rounded separately from w\*DPR/cell and h\*DPR/cell. It is then shown at width:100%;height:auto, so the displayed height follows cols:rows instead of the image's own ratio. In Chromium a 400x200 image rendered 400x201.5 at DPR 1 and 400x199.25 at DPR 2. With a large --cell (for example 64 on a 400x150 image: 6x2 cells) the canvas shows at 400x133, a visible distortion that also shifts the layout. — fix: Set the canvas's CSS aspect-ratio (or style.height) from nw/nh. Halftone already sizes from w,h.
- **--selector accepts unbalanced quotes or brackets, and --chars cannot start with '--'** — `.claude/helpers/kit/image-effects.js:110` (correctness): checkSelector only checks the character set, so 'img\[alt="x\]' is accepted (exit 0). The emitted CSS then has an unterminated string, which swallows the following rules, and the script's querySelectorAll throws an uncaught SyntaxError at the top level, outside the try/fallback. Separately, parse() rejects any value that starts with '--', so a plausible glyph ramp such as --chars '--==##' fails with exit 1 and '--chars needs a value'. — fix: Check that quotes and brackets balance in the selector (or wrap the script's querySelectorAll in the try). Apply the '--' value check only to flags that cannot legitimately start with '-' (not --chars).
- **Header says only the first match is treated, but duotone CSS applies to every match** — `.claude/helpers/kit/image-effects.js:12` (docs): The header says the selector 'names the image; only the first match is treated'. That holds for the canvas scripts, but the duotone CSS rule \`${selector}{filter:url(#id)}\` filters every element that matches. The canvas kinds' \`${selector}{display:block}\` rule also reaches every match. — fix: Limit the 'first match only' wording to the canvas kinds, and say that duotone applies to every element the selector matches.
