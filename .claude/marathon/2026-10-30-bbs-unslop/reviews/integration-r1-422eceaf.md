## Medium (4)

- **/mt slop gate: per-file measure lets the last clean file hide an earlier dirty one** — `src/plugins/dot-shortcuts.js:5440` (correctness): The 4.3c slop audit says to scan every changed screen file on each loop pass, and after each scan to record \`record measure key=slop\_\<s\> value=true\` on exit 0 or \`value=false\` on exit 2. All files of the stream write to the same key, and gate.js resolveSource (measure:) takes the LAST row for the key. Your own reach test checks this: met(\[false, true\]) === true. So a stream with two screens, where a.html still has slop (false) and b.html scanned after it is clean (true), meets \`slop\_\<s\>\`, and the blocking gate passes with unresolved signs. That is a normal input: most UI streams change more than one file. Installed copy: .claude/commands/.shortcuts/w-marathon.md:421. — fix: Record one measure per pass: value=true only when every changed screen file's scan exited 0, otherwise value=false. One way is to scan all files in one block and record from the combined status. Add a reach test with one dirty and one clean file.
- **/pt blocking do-not check is not enforced for a new screen (template-test always exits 0)** — `src/plugins/dot-shortcuts.js:1313` (correctness): The CHECKPOINT 6 Review step is BLOCKING ('failures stop the review'). For a new screen with no before version it says to run \`template-test --name "$PRODUCT\_NAME" --file "$AFTER"\` instead, but no block runs that command and nothing says to read \`pass\`. template-test has no --strict: it exits 0 even with pass:false. I probed it: a page without the product name, made only of generic sentences, gave pass:false and rc=0, and adding --strict gave rc=1 (unexpected argument). The text after the step reads 'Exit 0: no do-not violation and the template test passes; go on', so on this path a failed template test is read as a pass. New landing pages and new dashboards are a common case. Installed copy: .claude/commands/.shortcuts/w-plan-tdd-swarm.md:675. — fix: Add a block for the new-screen path and state that \`pass: false\` from template-test stops the review exactly like exit 2. Or have the no-before path go through a command that exits 2 on a false pass. Add a reach test for it.
- **/mt image gate stops the unattended loop to wait on AskUserQuestion, against 'Ask once'** — `src/plugins/dot-shortcuts.js:5359` (process): The 4.3c image gate says to 'put it to the user exactly as printed (AskUserQuestion) and wait for the answer' in the middle of the loop. /w-marathon's Rules say 'Ask once. After the kickoff is approved, the only questions left are the waitingOnHuman lines', and the Interview says Claude 'never stops to wait'. The spec row says 'declined means an empty slot, not a stalled loop', but an unanswered request (pending) stalls the loop for as long as the owner is away. A days-long run then sits idle on one image prompt. The kit-missing fallback has the same problem: it asks in plain words and waits. Installed copy: .claude/commands/.shortcuts/w-marathon.md:340. — fix: In /mt, while the request is pending: put the slot in place, list the request as a waitingOnHuman / checklist.md line (the report already lists pending requests) and carry on. Or collect the image approvals in the Interview batch. Never block the loop on an AskUserQuestion.
- **/mt slop finish line is added even without the kit, so a UI stream can never meet its gate** — `src/plugins/dot-shortcuts.js:5176` (correctness): The Interview adds the \`slop\_\<s\>\` line (source measure:slop\_\<s\>) for every UI, landing page or dashboard stream, whether or not the kit is installed. Only the 4.3c slop audit, which is kit-only, ever records that measure. In a project without .claude/helpers/kit/cli.js the step 'is skipped like every kit step', the measure is never written, gate.js returns NOT\_FOUND, and the stream's gate stays unmet forever. That breaks the promise that 'the kit is advisory and never blocks a workflow that worked before', and it hits every UI stream, not only the reference-design ones the fidelity line covers. — fix: Add the slop\_\<s\> line only when .claude/helpers/kit/cli.js exists, the same condition as the step that records it. Or record value=true with a 'kit not installed' note when the audit is skipped.
