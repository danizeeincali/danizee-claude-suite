- **Killed or timed-out ffmpeg reported as "exit null" with an empty tail** — `src/lib/kit/story-render.js:254` (correctness): exec() resolves { code: null } when the child dies by signal (including the 600 s SIGKILL timeout it sets itself, line 221), and the message is built from 'exit ' + enc.code. Probed with an --ffmpeg script that kills itself: stderr was \`kit: ffmpeg failed (exit null): \` with nothing after it. Neither the signal nor the timeout is named. The same applies to probeFfmpeg (line 231): a \`-version\` that hangs past 10 s is reported as \`ffmpeg not found ... (exit null ...)\` with exit 4, which is misleading because the binary exists. — fix: Resolve the close signal in exec() (on('close', (code, signal))), add a timedOut flag, and word the messages 'killed by SIGKILL' or 'timed out after N s' instead of 'exit null'.
- **ffmpeg exiting 0 without writing the output surfaces a raw ENOENT rename error** — `src/lib/kit/story-render.js:255` (correctness): If the encoder exits 0 but writes no file (probed with --ffmpeg /bin/true, which passes the -version probe), fs.rename throws a plain Error. cli.js prints \`kit: ENOENT: no such file or directory, rename '.../o.mp4.\<pid\>.part.mp4' -\> '.../o.mp4'\` and exits 1. The exit code is right, but the message does not say that ffmpeg produced no output. — fix: Stat tmpOut after a 0 exit, and throw bad('ffmpeg exited 0 but wrote no output ...') when it is missing or empty.
- **--keep-frames with a capture failure leaves an unnamed temp folder** — `src/lib/kit/story-render.js:252` (correctness): When keepFrames is set, the finally block (line 264) skips removing framesDir on every path. If capture returns exit 4 (line 252), or throws because the page load, a screenshot or the clock fails, the temp folder (empty, or holding partial frames) stays in os.tmpdir(). Neither the result nor the error names it, unlike the encode-failure path at line 254, so the user cannot find it or clean it up. — fix: Remove framesDir whenever no frames were captured, or add frames\_dir to the exit-4 result and append 'frames kept in \<dir\>' to a capture error when --keep-frames is set.
- **An interrupted render leaves the temp frames and .part.mp4 behind** — `src/lib/kit/story-render.js:248` (correctness): Cleanup relies on the finally block alone. A Ctrl-C or SIGTERM during a long capture or encode (up to 120 s x 60 fps = 7200 full-HD PNGs) ends Node without running it, so story-render-\* in os.tmpdir() and \<out\>.\<pid\>.part.mp4 stay on disk. The power brief says the temporary frame folder is removed. — fix: While render runs, register SIGINT/SIGTERM handlers that remove framesDir (unless --keep-frames) and tmpOut synchronously, then re-raise the signal. Remove the handlers in finally.
