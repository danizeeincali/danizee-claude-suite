## High (1)

- **capture hangs forever on an asset response that never finishes; --timeout-ms does not bound it** — `src/lib/kit/page-snapshot.js:779` (correctness): Every image/font/stylesheet response pushes an async job that awaits r.body() with no timeout, and capture then does \`await Promise.all(bodies)\`. A body that never completes (an MJPEG/live camera image, a long-poll or stalled chunked asset, here an \<img\> added after load whose server keeps writing) makes the verb hang with no bound. Probe: 127.0.0.1 server whose page adds an image after load that streams one byte every 500 ms; \`capture --url http://127.0.0.1:18923/ --out ... --timeout-ms 5000\` was still waiting at 120 s (pw:api trace: response.body started, networkidle wait failed at 5 s, then nothing until the process was killed, then 'the screenshot failed: Target page, context or browser has been closed'). The documented --timeout-ms only covers goto and settle. Applies to the copied helper too (.claude/helpers/kit/page-snapshot.js). — fix: Race each r.body() (or the whole Promise.all(bodies)) against a timer derived from --timeout-ms; a body that misses it is recorded as not captured (e.g. skipped 'response did not finish in time'). Add a real-capture test with a never-ending image response that asserts the capture finishes within the timeout.

## Medium (2)

- **redirected images are never inlined and are listed as 'the page never loaded it'** — `src/lib/kit/page-snapshot.js:742` (correctness): Captured bodies are keyed by r.url(), the URL of the final response after redirects, while the copy looks assets up by the element's own URL (img src / currentSrc is the pre-redirect URL). Any image behind a redirect (common for CDNs, /avatar endpoints, same-origin 302s) therefore keeps its remote URL and gets the false skip reason 'the page never loaded it'. Probe on 127.0.0.1: \<img src=/redir.png\> with 302 to /b.png gave inlined:\[\] and skipped:\[{url:'.../redir.png', reason:'the page never loaded it'}\], although the browser loaded and displayed it. — fix: When storing a response body, also store it under every URL of its redirect chain (walk r.request().redirectedFrom()), subject to the same private-address check per hop; add a test with a 302'd image.
- **remote mode's forced --no-proxy-server fails behind a mandatory proxy with a misleading error and no option** — `src/lib/kit/page-snapshot.js:656` (docs): Remote captures now always launch Chromium with --no-proxy-server (and Node does its own DNS lookups, a failure counting as private). The trade is defensible (through a proxy serverAddr would be the proxy's address and the post-hoc private check would be meaningless), but on a network that only allows egress through HTTP(S)\_PROXY (corporate networks, this agent sandbox) a remote capture the user consented to fails as \`could not load \<url\>: net::ERR\_...\` (exit 1, line 760) with nothing saying the proxy was bypassed on purpose, and every cross-origin asset whose DNS lookup fails is silently aborted and only shown in blocked\_origins. The behaviour is stated only in one clause of the header comment; the usage string, the exit-code table and the error text do not mention it, and there is no flag to opt in to a proxy. — fix: Keep the default, but when remote navigation fails and HTTP\_PROXY/HTTPS\_PROXY/ALL\_PROXY is set, say so in the error (e.g. 'remote mode connects directly, without the configured proxy'); mention it in usage. Optionally add an explicit --proxy-ok flag that uses the proxy and turns off the serverAddr check (documented as weaker).

## Low (2)

- **an ambient KIT\_EGRESS\_ALLOW\_EXEC leaks into every packaged test's guard** — `test/helpers/no-egress.mjs:15` (test-quality): The harness (test/helpers/packaged.js env()) spreads process.env and overrides KIT\_EGRESS\_LOG and KIT\_EGRESS\_ALLOW\_DIR but not the new KIT\_EGRESS\_ALLOW\_EXEC. If a developer or CI job has it exported (for example after running this suite by hand), every other packaged test silently allows child processes from those folders, weakening their zero-egress assertions without any sign. With the variable unset, nothing changes for other tests (verified: kit-infra 7/7 pass). — fix: In packaged.js env(), set KIT\_EGRESS\_ALLOW\_EXEC: '' before ...extra so only a test that passes it through extraEnv gets the allowance.
- **exit 4 table omits the old-playwright and remote-guard failures** — `src/lib/kit/page-snapshot.js:714` (docs): The exit-code section says 4 means 'playwright or its browser is missing', but capture also returns exit 4 for 'playwright \>= 1.48 required' (line 662) and 'the browser cannot apply the remote address guard' (line 714). A caller reading the table cannot tell these apart from a missing install. — fix: List all three causes under exit 4 in the header and usage string.
