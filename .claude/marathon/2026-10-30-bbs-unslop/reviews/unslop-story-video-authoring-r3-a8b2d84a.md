## High (1)

- **Swap text lands at the left edge of a centred element, not where the old text was** — `src/lib/kit/story-plan.js:504` (correctness): \<story-swap\> is display:block (line 527) then position:absolute with auto insets, so its static position is the left of the element's content box. text-align is ignored. Probed in Chromium 153 with emitted pages: in a centred h1 the old text spans x 378-702 and the new text x 0-251. In a \<button class=btn\> (the shape template() swaps) the old text spans x 79-221 and the new text x 12-39. Centred headings and buttons are the normal case for a swap, so the new text visibly jumps sideways on most real stories. No test measures where the new text lands against the old. — fix: Place the swap over the old text's line box: for example, have the parse-time script copy the computed text-align and size the swap to the content box (left:0;right:0 with the element made the containing block only during the swap). Or measure the old text's range rect once and set left/top. Add a Playwright check that compares the old text's range rect with the new text's rect for a text-align:center element and a \<button\>.

## Medium (3)

- **Selector camera measures before loading=lazy images load, so the crop misses its target** — `src/lib/kit/story-plan.js:554` (correctness): The header (line 76) says the camera is measured on the load event with 'images loaded'. Lazy images below the 1080px clip of #story-page do not delay load and only start after the camera moves the page. Nothing then re-aims the camera. Probe: a page with a lazy \<img\> (no width/height) above #target. fit() ran with the image at 0px. The image then loaded at 574px, and #target finished at y=1088, outside the 1080 frame, on every frame. With a rect camera the same images pop in after frame 0. loading=lazy is common in CMS and production pages. — fix: In preparePage, rewrite loading="lazy" to eager (or drop the attribute) so every image counts toward load. Or re-run fit() on each img load event. Correct the header's 'images loaded' claim either way, and add the lazy-image case to the camera Playwright test.
- **Without the script (JS blocked, sandboxed preview) a swapped element goes blank** — `src/lib/kit/story-plan.js:499` (correctness): The swap's fade-out and the hide slot are pure CSS on the element (lines 494-499). The new text exists only once the parse-time \<script data-story-marks\> inserts \<story-swap\>. Wherever that script does not run, the old text fades to transparent and stays hidden: an iframe without allow-scripts, a CSP that blocks inline script, an older viewer with JS off, or a tool that strips scripts. The button or heading is left empty from mid-step to the end. Before this round the swap was CSS-only and degraded with it. — fix: Gate the swap's element-side animations on the script having run. For example, the script adds class story-marks to \<html\>, and the swap slot and hide rules use html.story-play.story-marks. Without the script the old text then simply stays.
- **The page loses the browser's default 8px body margin, so frame 0 is offset from the original** — `src/lib/kit/story-plan.js:588` (correctness): The real \<html\>/\<body\> get margin:0 and the page's body content goes into a plain #story-page div, which has no UA body margin. scopeCss carries over only the page's own body rules. So a page that does not reset body margin is drawn 8px up and left of the original, and 16px wider. Its 'before' frame no longer matches the screen being redesigned, and a camera {x,y,w,h} measured on the original page is 8px off. Every fixture writes body{margin:0} or style="margin:0" (test lines 18, 581, 682, 730), which hides this. — fix: Wrap the page body in an inner element that takes the UA body defaults (margin:8px, so margins collapse as in the original) inside the fixed-size #story-page, with the page's scoped body rules on that inner element. Add a frame-0 pixel test on a page without a margin reset.
