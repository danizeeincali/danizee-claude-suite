## Medium (1)

- **SIGTERM during the encode orphans the ffmpeg child** — `src/lib/kit/story-render.js:268` (correctness): onSignal cleans the files and re-raises, but nothing kills the ffmpeg child spawned by exec() (line 224), and the 600 s kill timer dies with node. A SIGTERM sent only to node (from \`timeout\`, a CI cancel, a supervisor or \`kill \<pid\>\`) leaves ffmpeg running under PPID 1. Probe: real Playwright and ffmpeg, 10 s square story, \`kill -TERM \<node pid\>\` once the .part.mp4 appeared. Node died with 143, but ffmpeg was still alive with ppid 1. With --keep-frames the orphan encoded the whole sequence and ran 6.5 s after node died. Without it, ffmpeg ran until it hit the deleted frames. For the largest allowed render (120 s, 60 fps, wide) on older or single-core hardware, that is minutes of CPU after the tool reported it had stopped. Ctrl-C in a terminal only works because the TTY signals the whole process group. — fix: Have exec() record the live child, for example in a set the render can reach. In onSignal (and in the finally), call child.kill('SIGKILL') or child.kill(sig) on it before re-raising. Add a real-ffmpeg or stub-child test that checks the child pid is gone after the parent gets SIGTERM.

## Low (4)

- **Signal test fires a real SIGINT/SIGTERM event at the whole test process** — `test/kit-unslop-story-video-renderer.test.js:425` (test-quality): process.emit(sig, sig) calls every SIGINT/SIGTERM listener in the process, not only the ones story-render added. The suite passes under the default per-file isolation. Under \`node --test --experimental-test-isolation=none\` (Node 22; \`--test-isolation=none\` in later Node), the runner's own termination handler fires: the run stops after 'r2 failure paths' subtest 4 with exit 1 and no summary. The test also passes even if render's handler never runs, as long as some other listener happens to clean up. — fix: Compare process.listeners(sig) before and during the render and call only the new listener directly. Do not emit the event process-wide.
- **ffmpeg probe does not check for libx264, so builds without it fail only after the full capture** — `src/lib/kit/story-render.js:243` (correctness): The header promises ffmpeg is probed before any frame is captured, but the probe only runs \`-version\`. Distro builds without libx264 pass the probe, for example Fedora's ffmpeg-free and some LGPL static builds. The render then captures every frame (minutes for a 120 s story) and only then fails with 'Unknown encoder libx264' as exit 1. That is not the documented exit 4 for 'ffmpeg missing'. — fix: Also run \`\<bin\> -hide\_banner -encoders\` in probeFfmpeg and require the libx264 line. Otherwise return exit 4 with a reason naming the missing encoder.
- **Fixed 600 s encode timeout can kill the largest allowed render on older hardware** — `src/lib/kit/story-render.js:220` (performance): The cap allows 120 s x 60 fps x 1920x1080 = 7200 frames. Measured with the verb's libx264 settings (crf 18, preset medium) on synthetic 1080p frames: 600 frames took 12.2 s on 4 threads, 18.6 s on 2 threads and 32.4 s on 1 thread. At 7200 frames that is about 150 s, 220 s and 390 s, before any PNG decode cost. An older dual-core or single-core box crosses 600 s and is SIGKILLed after the whole capture is done. No flag raises the limit. — fix: Scale the timeout with the frame count (for example max(600 s, frames x 200 ms)), or add an --encode-timeout flag and document it.
- **Signal path prints a misleading capture error and never names the --keep-frames folder** — `src/lib/kit/story-render.js:268` (other): A SIGTERM during a real capture ends with exit 143, but stderr reads 'kit: frame 23 of 300: the screenshot failed: page.screenshot: Target page, context or browser has been closed'. Playwright's SIGTERM handler closes the browser and the rejected capture is printed before the 100 ms fallback exit, so the operator sees a bogus screenshot bug instead of 'interrupted'. With --keep-frames, the signal path is the one failure path that never says where the frames were kept. — fix: In onSignal, set a flag and write one stderr line such as 'story-render: interrupted by SIGTERM' plus '; frames kept in \<dir\>' when --keep-frames is set. Have the catch skip printing the capture error once the flag is set.
