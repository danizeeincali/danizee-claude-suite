## Medium (3)

- **MB is recorded after the branch push, so the main re-check never matches the branch's receipt** — `src/plugins/dot-shortcuts.js:3771` (correctness): The text pushes the branch first, then sets MB=$(git merge-base @{upstream} HEAD). A successful push moves the remote-tracking ref, so MB is HEAD, not the base the branch check used. push-gate check --base "$MB" on main then hashes a different id and returns ask 'only an earlier review exists…' even on a fast-forward. The no-upstream path mismatches too (branch check base null, main check resolves main's upstream). — fix: Record MB right after the branch gate check, before pushing, and reuse it; for a branch with no upstream say the main check will ask, or reuse the branch check's base.
- **git restore --staged does not exist before git 2.23; a failed unstage leaves secret-bearing paths staged** — `src/plugins/dot-shortcuts.js:3716` (correctness): restore was added in git 2.23; on older git it fails with 'not a git command' and nothing checks the exit, so the paths holding the scrub hit stay staged and the user's next plain git commit would commit them. — fix: Use git reset -q -- \<paths\>, which works on every git, or fall back to it when restore fails, and report a non-zero exit.
- **A branch push that fails still leads to the merge into main, the main push and the clean-up** — `src/plugins/dot-shortcuts.js:3771` (correctness): Nothing checks the branch push's exit status. Offline or rejected, the agent goes on to merge into local main, run the main gate, attempt the main push and clean up the branch, and the summary has no failed-push wording. — fix: After a non-zero exit from the branch push stop Phase 3 (no merge, no main push, no clean-up) and write 'not pushed — push failed (exit N): \<stderr\>' into the summary; same for a failed main push.

## Low (1)
