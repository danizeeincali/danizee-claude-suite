- **Secrets pre-check reads a broken secrets file as 'nothing to redact'** — `.claude/commands/.shortcuts/w-bbs.md:128` (correctness): The CHECKPOINT 4 block uses \`\[ ! -f .claude/kit/secrets \]\` to short-circuit before redact. \`-f\` is false for a dangling symlink or a directory at that path, so the block prints 'no .claude/kit/secrets: evidence recorded as is, nothing to redact' and exits 0. In those cases redact itself exits 1: readFileOr treats a dangling symlink as broken, not absent, and a directory gives EISDIR. Verified in a scratch repo. Dangling symlink: block rc=0 'nothing to redact', direct \`redact\` rc=1 'cannot read secrets file ... ENOENT'. Directory: block rc=0, direct rc=1 EISDIR. A broken state that the verb reports as exit 1 is turned into a clean 'nothing to redact', which the run's rules forbid. The text right below says 'never read exit 1 as nothing to redact'. The test at test/w-bbs-command.test.js:291 pins this wording. — fix: Drop the secrets pre-check (redact already returns replaced=0 when the default file is truly absent), or test with \`-e\`/\`-L\` instead of \`-f\` so anything present at the path goes to redact and its exit 1 surfaces. - **Refused scrub leaves the run's paths staged, with the hit in the index** — `.claude/commands/.shortcuts/w-bbs.md:166` (security): CHECKPOINT 6 runs \`git add -- .claude/bbs/runs/\<id\>\` (and the registry) before \`scrub --worktree\`. On exit 2 with hits in those paths, it only says not to run /bc until the hits are removed. It never unstages, and it never says to re-add after the fix. scrub --worktree reads files on disk, so after the user edits out a hit, a re-scan is clean while the index still holds the staged blob with the secret. A plain \`git commit\` by the user, or a stop at this point, keeps that secret-bearing blob in the index. /bc's own refused-scrub path does unstage (\`git reset -q -- \<paths\>\`, w-background-compound.md:107), so the two disagree on the same error path. — fix: On any non-zero scrub exit (and on a failed git add), run \`git reset -q -- .claude/bbs/runs/\<id\> .claude/bbs/registry.jsonl\` and check its exit, as /bc does. Or say the paths must be re-added after the hits are removed and before the re-scan.
- **Redacted evidence from untrusted source is pasted into a double-quoted shell argument** — `.claude/commands/.shortcuts/w-bbs.md:130` (security): The new redact step keeps the evidence in a file ($E, then $J), prints the redacted \`text\`, then says 'Use the printed text as the evidence ... verdict --probe ... --evidence "\<text\>"'. This evidence quotes the fetched, untrusted source, and probes hunt for network calls, so it often holds JS template literals such as fetch(\`${BASE}/t\`). Inside double quotes, backticks and $( ) run as commands and ${X} expands, which corrupts the record and executes text derived from the clone. The shape predates this diff, but the diff rewrote this line and already had the evidence in a file, where a safe hand-off costs nothing. — fix: Write the redacted text to a file $R inside the block and record it with \`--evidence "$(cat "$R")"\` (command-substitution output is not re-evaluated), or add an --evidence-file flag.
