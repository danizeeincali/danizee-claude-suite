## Low (4)

- **Scrub-before-commit scans the files on disk, but git commits the index** — `src/plugins/dot-shortcuts.js:4833` (correctness): w-end (and w-agent-tdd-swarm line 1209, w-autoresearch line 3806) says to stage and then run \`scrub --worktree\`. That mode lists index entries but reads each file's content from disk. A secret staged and then edited out on disk without re-staging passes the scrub and is committed. Unstaged edits or an unstaged deletion of an unrelated tracked file make the scan refuse a clean commit (a tracked file missing on disk gives incomplete, exit 2). 'Commit only after the scrub exited 0' does not guarantee the committed blobs were scanned. — fix: Before the scrub, require \`git diff --quiet\` (no unstaged changes to tracked files), or say so explicitly. Or run \`scrub\` (HEAD mode) right after the commit and roll back with \`git reset --soft HEAD~1\` on a refusal.
- **Closing step (w-tdd-swarm, w-debug, w-hotfix, w-security) leaves receipt and scrub error exits partly unnamed and does not make the receipt depend on the scrub** — `src/plugins/dot-shortcuts.js:473` (process): The closing-step receipt text (lines 473, 1915, 2192, 2707) names exits 0, 1 and 2 only; it never says what any other non-zero exit means. The scrub text says 'do not commit' only for exit 2. 'Then record the counts' follows a scrub refusal without any condition, and 'stop' conflicts with Compound's NEVER SKIP. So a passing receipt can be recorded for a tree whose scrub refused or failed. — fix: Add 'Any other non-zero exit is a failure of the step: name the exit code, never read it as recorded' to the receipt text. Add 'do not commit' to scrub exit 1 and other exits. Say 'after a scrub refusal or failure, record no receipt; continue to Compound'.
- **w-ralph-pick's lenses-only step talks about a removal check that never runs there** — `src/plugins/dot-shortcuts.js:5633` (docs): The shared range sentence says that with no upstream 'removed\_with\_live\_callers cannot find removals, so say the removal check did not run'. w-ralph-pick runs lenses only and has no impact step, so no removal check runs in any case. — fix: For the lenses-only variant, drop the removed\_with\_live\_callers clause, or say 'no removal check runs in this workflow (lenses only)'.
- **w-autoresearch: a refused Keep is reverted as a Crash, but the revert leaves the refused new files on disk** — `src/plugins/dot-shortcuts.js:3797` (correctness): On a scrub refusal the paths are unstaged and the experiment is treated as a Crash ('revert'). The only revert command in the loop is Discard's \`git checkout -- .\`, which does not remove new untracked files. A new file that held the hit stays on disk, untracked, and is not scanned by later \`scrub --worktree\` runs. There is also no rule for repeated refusals in a loop that 'NEVER aborts'. — fix: Spell out the Crash revert after a scrub refusal: \`git checkout -- . && git clean -fd -- \<the experiment's new paths\>\`. Pause the loop (create .autoresearch-off) after N consecutive scrub refusals and log why.
