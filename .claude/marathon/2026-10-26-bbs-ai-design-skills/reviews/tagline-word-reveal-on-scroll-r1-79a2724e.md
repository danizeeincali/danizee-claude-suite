## Medium (5)

- **emit has no stdin input path; tests never drive stdin** — `src/lib/kit/word-reveal.js:175` (correctness): Shared conventions say input comes from a file or stdin, and the Input reading rule says stdin is read with io.stdinBytes({ maxBytes: MAX + 1 }) with the cap counted in bytes. run() only accepts --text-file and ignores io.stdin/io.stdinBytes, so \`... | cli.js word-reveal emit\` exits 1. The rule also requires unit tests that drive stdinBytes (an over-cap multibyte input and a happy path) and a packaged test that drives both stdin and --file. None of these tests exist (the unit io stub even passes a stdin that is never used). — fix: When --text-file is absent and stdin is not a TTY, read io.stdinBytes({ maxBytes: MAX\_BYTES + 1 }), refuse more than MAX\_BYTES bytes with exit 1, and decode as UTF-8. Add the unit tests for stdinBytes and the packaged stdin and --file cases.
- **File read is size-checked by stat, not bounded** — `src/lib/kit/word-reveal.js:166` (correctness): readFileCapped checks st.size and then calls fs.readFile on the whole file. The rule requires a bounded read of at most 8 MiB + 1 bytes. A file that grows between the stat and the read, or a regular file that reports size 0 but has content (for example under /proc), is read in full with no cap. That holds for both emit --text-file and lint --file. — fix: Open the path, fstat the handle (isFile), read at most MAX\_BYTES + 1 bytes into a buffer, and exit 1 if more than MAX\_BYTES bytes came back.
- **Repeated flags are silently last-wins; an empty --text-file gives a misleading message** — `src/lib/kit/word-reveal.js:161` (correctness): parse() does flags\[k\] = rest\[++i\] with no duplicate check. \`emit --text-file a.txt --text-file b.txt\` emits b's text, and \`--muted 0.3 --muted 0.9\` uses 0.9. Both were confirmed by running them. The Input reading rule says a repeated flag is refused with exit 1. \`--text-file ""\` resolves to the cwd and fails with '\<cwd\> is not a regular file' instead of naming the empty value. A flag value that starts with -- (for example \`--text-file --muted\`) is also taken as the value. — fix: In parse(), throw bad(\`${a} given twice\`) if k is already in flags. Refuse an empty value, or one that starts with --, with a message that names the flag.
- **Screen readers may announce the tagline as word fragments** — `src/lib/kit/word-reveal.js:69` (accessibility): The fragment is a bare \<p\> holding one \<span\> per word, with no accessible-name strategy. Some screen readers, notably VoiceOver on iOS and Safari, treat each inline span as its own swipe stop, so the sentence is read one word at a time. Nothing gives assistive technology the whole sentence as one unit, and no test checks for it. Putting aria-label on the \<p\> is not a reliable fix, because ARIA prohibits naming the generic or paragraph role. — fix: Emit the full escaped sentence once in a visually-hidden span (sr-only CSS), and wrap the word spans in an aria-hidden="true" span. Add a test asserting both.
- **Words stay at muted opacity forever when the script never runs or the block is skipped** — `src/lib/kit/word-reveal.js:73` (accessibility): The muted opacity is applied by plain CSS (.wr-w{opacity:0.25}), regardless of JavaScript. If the inline script is blocked (CSP without unsafe-inline, JS off, a sanitizer that strips \<script\>), the tagline is stuck at 25% opacity, which is far below text-contrast minimums. The observer callback (line 86) also reveals only on isIntersecting. If the page loads already scrolled past the block (scroll restore, or an anchor link below it), the block is above the root box and never intersects, so it stays dim until the user scrolls back up. — fix: Apply the muted state only under a class the script adds (for example, the script sets .wr-js on the \<p\>, and the CSS rule becomes .wr-js .wr-w{opacity:muted}). In the callback, also reveal when entry.boundingClientRect.top \< entry.rootBounds.top, meaning the block has already been passed.

## Low (2)

- **Lint treats any mention of 'throttle' or 'rAF' as throttled** — `src/lib/kit/word-reveal.js:95` (correctness): THROTTLE\_RE is tested against the raw handler text, comments and strings included. A handler with a comment like \`// TODO throttle this\`, or a call to an unrelated function named debounceLog, is passed as throttled. The result is a silent false negative for exactly the case the lint exists to catch. — fix: Strip comments and string literals from the handler before testing, and match call sites only, for example /\b(requestAnimationFrame|rAF|throttle|debounce)\s\*\(/.
- **Non-breaking spaces are split into ordinary breaking spaces** — `src/lib/kit/word-reveal.js:59` (correctness): split(/\s+/) also matches U+00A0. A tagline written with an intentional non-breaking space (for example '10 km' or 'Mr. Smith') is emitted as separate spans joined by a normal space, so the author's no-wrap intent is lost at large font sizes. — fix: Split on /\[ \t\r\n\f\v\]+/ (ASCII whitespace) so that U+00A0 stays inside a word.
