## Medium (3)

- **Spec check reads a markdown spec as HTML when it opens with any tag** — `src/plugins/dot-shortcuts.js:907` (correctness): The Spec step runs \`landing-sections check --file "$SPEC"\` without \`--format\`. Since the r2 fix, sniff() (src/lib/kit/landing-sections.js:246) treats any text that starts with \`\<tag\` as HTML and ignores the .md extension. A markdown spec that opens with an inline tag (an anchor \`\<a id="top"\>\</a\>\`, a \`\<div align="center"\>\` badge row, \`\<details\>\`) loses every heading. Probe: '\<a id="top"\>\</a\>\n\n# Hero ... ## Final CTA \[Start free\](/x)' as s.md returns found: \[\] with every section missing, while the same file with \`--format md\` finds hero and final-cta. The step always passes a markdown spec (.claude/plans/\*.md), so a wrong 'missing' list on a normal spec misleads the agent. — fix: Pass \`--format md\` in the Spec step's check line (the input is always the markdown spec), and add a reach or unit case for a .md spec that opens with an inline tag.
- **Marathon fidelity 'unmet build gate' never reaches the scripted gate** — `src/plugins/dot-shortcuts.js:5033` (process): The 4.3b fidelity step says exit 2 is 'an unmet build gate, and the stream is not done until it passes', but nothing records the result. 4.8 marks the stream done when \`cli.js gate --stream \<s\>\` exits 0, and that gate reads only runs.streak, reviews, findings and measures (finish-line.json). A failing fidelity score leaves no row, so the gate can pass and 4.8 tells the agent to set state=done and start the next stream. rules.md says 'Scripts decide, the model acts: ... gates ... come from cli.js'. The integration row ('treat a score under target as an unmet build gate') is therefore enforced only by prose that conflicts with 4.8. — fix: On fidelity exit 2 tell the agent to record \`cli.js record run kind=build status=red stream=\<s\>\` (green on exit 0), and make the stream's finish line read runs.streak:build, or record a measure the gate checks.
