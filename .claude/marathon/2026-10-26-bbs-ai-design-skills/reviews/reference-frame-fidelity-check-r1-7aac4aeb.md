## High (2)

- **Box blur erases period-(2r+1) content: a visibly different frame passes as identical** — `src/lib/kit/fidelity.js:183` (correctness): The PSNR is computed only on box-blurred images, and a box filter of window 2r+1 has exact spectral zeros. Any difference whose pattern has period 2r+1 along a row (e.g. +d,-2d,+d repeating, which also survives the clamped edges when the width is a multiple of 3) blurs to zero. Confirmed: a 6x6 uniform gray 100 ref against vertical stripes 140/20/140 (raw PSNR about 10 dB) gives {psnr:null, identical:true, pass:true} at the default --blur 1. Regions use the same blurred buffers, so they do not catch it either. For a blocking judge this is a wrong pass on 1px periodic content such as dotted borders, hatching or dithering, and identical:true (line 269) claims the frames are equal when they are not. — fix: Use a gaussian blur, which has no spectral zeros (the contract allows box or gaussian), or apply a floor from the unblurred PSNR. Compute identical from the raw composited pixels, not from the blurred MSE. Add a test with a period-3 stripe pattern that must fail.
- **A --diff-out write error replaces a failing verdict with a non-blocking exit 1** — `src/lib/kit/fidelity.js:368` (correctness): run() computes the verdict (exit:2 on a failure) and then calls writeAtomic. If the diff cannot be written (parent directory missing, read-only, the path is a directory or a symlink), writeAtomic throws KitExit 1 and the verdict is lost. exit-codes classes 1 as 'usage', which never blocks, so a failing frame passes the UI gate. Confirmed: --ref solid(100) --actual solid(180) --diff-out nodir/d.png throws code 1 (ENOENT) instead of returning exit 2. A CI step that writes the diff into an artifacts/ folder nobody created is a normal setup, and every failing frame then gets through. — fix: Check that the --diff-out target can be written before comparing, or catch the write error once the verdict is known, keep exit 2 and report the write problem in the result (e.g. diff\_out\_error). Add a test: a failing compare with an unwritable --diff-out still gives exit 2.

## Medium (2)

- **50-megapixel cap lets a 190 KB PNG pair use 4.5 GB RAM and take 68 s** — `src/lib/kit/fidelity.js:36` (security): MAX\_PIXELS allows 50M pixels, and the working set grows to many times the pixel count: raw, unfiltered and RGBA byte buffers for each image, plus a Float32 composite, blur tmp and blur out for each image, plus a second blur pair for the structural retry, plus another composite pair in diffPng. Measured: two 7000x7000 RGBA PNGs of 190 KB each, with one failing region, reached 4542 MB max RSS and took 67.8 s. inflateSync's maxOutputLength bounds only the inflate, not what follows. On a smaller CI runner this ends in an OOM kill, which is infrastructure (non-blocking), so a hostile or accidental huge actual frame also gets past the judge. — fix: Lower MAX\_PIXELS to a size that fits real UI frames (e.g. 16 MP), or budget memory from width\*height\*bytes per stage. Free the raw and out buffers early, reuse blur buffers, and blur only the failing regions' bounding boxes for the retry.
- **--diff-out can overwrite the --ref or --actual input** — `src/lib/kit/fidelity.js:306` (correctness): writeAtomic refuses symlinks and non-regular files, but it does not check that the target differs from the input files. Confirmed: --ref ref2.png --actual off.png --diff-out ref2.png replaces the reference frame with the amplified diff image. Every later run then compares against a diff picture, so the reference is lost (data loss) and later verdicts are wrong. — fix: Resolve --diff-out and refuse it with exit 1 when it equals the resolved --ref or --actual (also compare dev+ino when the file exists).

## Low (4)

- **Unknown critical chunks and out-of-order PLTE/tRNS are accepted silently** — `src/lib/kit/fidelity.js:83` (correctness): The chunk loop ignores every type it does not know, including critical ones (uppercase first letter), which the PNG spec says a decoder must reject. It also accepts PLTE or tRNS after IDAT. The decoder can therefore score a file it cannot actually interpret, instead of refusing it with a clear message. — fix: Refuse an unknown chunk whose type byte 0 is uppercase (bit 5 clear), and refuse PLTE or tRNS after the first IDAT, with KitExit 1.
- **readBounded checks the path with stat, then opens it (TOCTOU)** — `src/lib/kit/fidelity.js:287` (security): isFile() is checked on the path before fs.open, so a path swapped to a FIFO between the two calls blocks open/read forever, which is the hang the Input reading rule's FIFO refusal is meant to prevent. — fix: Open first with O\_RDONLY|O\_NONBLOCK (and O\_NOFOLLOW if wanted), then fh.stat() and check isFile() on the open handle.
- **Test named for FIFO refusal never uses a FIFO or /dev/stdin** — `test/kit-reference-frame-fidelity-check.test.js:230` (test-quality): 'input rules: directories, FIFOs-like non-regular files...' only tests a directory. The rule names FIFO, device and /dev/stdin refusal specifically, so a regression in that path would not be caught. — fix: Add a case for --ref /dev/stdin (or a mkfifo FIFO on POSIX) that must exit 1 with 'not a regular file' and must not hang.
- **Regression description now misleads for fidelity** — `.claude/helpers/kit/exit-codes.js:56` (docs): Once fidelity is in PRODUCT\_JUDGES, classify/describe for a fidelity exit 2 returns the generic regression text: 'Pass --result ... for the hit count, the first unscanned paths with reasons and a remedy'. None of that applies to a PSNR verdict, and passing --result adds nothing, so the text sends the reader after information that does not exist. — fix: Make the generic text verb-neutral, or add a fidelity description that reads frame psnr/target and the failing region ids from --result.
