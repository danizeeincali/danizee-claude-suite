## Medium (2)

- **Heading name trim /#+$/ is quadratic on a long run of #** — `src/lib/kit/landing-sections.js:94` (performance): The new heading code strips closing hashes with m\[2\].trimEnd().replace(/#+$/, ''). On a run of n '#' followed by any other character, V8 retries the greedy #+ from every start position, so the cost is O(n^2). Measured: 10k hashes take 97 ms, 20k take 312 ms and 40k take 1221 ms. A 2 MB line such as '## Hero ' + '#'.repeat(2\*1024\*1024) + 'x' did not finish within 20 s. This breaks the 'linear time on capped input' rule. The new timing test covers trailing spaces ('md heading spaces') but not trailing hashes. — fix: Strip the closing sequence with a backward loop: walk back from the end over '#' and then require a space, tab or start before it, as CommonMark does. Add '## Hero ' + '#'.repeat(MB2) + 'x' to the 2 MB timing cases.
- **Text-only sniff now reads common .html files as markdown** — `src/lib/kit/landing-sections.js:429` (correctness): The type used to come from the extension, so --file page.html was always parsed as HTML. Now sniff() decides from the text alone, using a short list of opening tags. An HTML file or fragment that opens with any other tag (\<meta\>, \<title\>, \<link\>, \<template\>, \<img\>, \<span\>, \<form\>, \<table\>) is parsed as markdown. Probe: '\<meta charset="utf-8"\>\<title\>x\</title\>\<section id="hero"\>...\<section id="final-cta"\>...' returns found:\[\] and lists every section as missing, where the same file named .html used to find hero and final-cta. That is a regression and a wrong result for existing --file \*.html users. The carried finding offered --format as the alternative. — fix: Add --format md|html, and keep sniffing only as the fallback for stdin and --file alike. Or sniff HTML from any leading '\<' followed by a tag name or '!doctype'. Add a test for a .html file that opens with \<meta\>.

## Low (4)

- **Reduced-motion allowance also passes media queries that apply without reduced motion** — `src/lib/kit/bg-fill.js:598` (correctness): The allowance only checks that every @media prelude contains '(prefers-reduced-motion: reduce)'. '@media (prefers-reduced-motion: reduce), (max-width: 600px)', '@media not all and (prefers-reduced-motion: reduce)' and '... or (min-width: 0)' all pass with exit 0 (probed). Each of these also applies to users who did not ask for reduced motion, so the judge lets the fixed background be turned off for everyone. — fix: Accept only a prelude that is exactly '@media (prefers-reduced-motion: reduce)', optionally with 'screen and' or 'and (...)' conjunctions, and refuse any comma, 'not' or 'or'. Add those three cases to the test as exit 2.
- **openRegular copies still read stdin through a symlink to /proc/self/fd/0** — `src/lib/kit/landing-sections.js:399` (security): The openRegular added to design-brief.js, landing-sections.js and type-scale.js checks fs.realpath(p) against /dev and /proc. When stdin is redirected from a regular file, realpath follows /proc/self/fd/0 through to that file, so a symlink link.md -\> /proc/self/fd/0 is not refused. Probe: 'landing-sections check --file link.md \< in.md' and 'type-scale audit --file link.md \< in.md' exit 0, and design-brief reads stdin. This is the defect carried for entrance.js, which was fixed there with an fd-0 dev/ino comparison but not in the three new copies. rules.md says to refuse any path that resolves under /dev or /proc. — fix: Share one opener across the four verbs. Walk the link chain with readlink hop by hop and refuse any hop under /dev or /proc, or compare fh.stat() dev/ino with fstat(0) as entrance.js does. Add the symlink case to each verb's tests.
- **Same-as-stdin check converts Number dev/ino to BigInt** — `src/lib/kit/entrance.js:145` (correctness): fh.stat() returns Number stats, so BigInt(st.ino) has already lost precision for inodes above 2^53, and the comparison with the bigint fstatSync(0) can miss a real match. This is the precision issue that fidelity.js fixed in this same diff by using bigint stats. — fix: Use await fh.stat({ bigint: true }) for the comparison.
- **Odd-length UTF-16LE is silently truncated while odd-length UTF-16BE is refused** — `src/lib/kit/sample-content.js:498` (correctness): decodeText refuses truncated UTF-16BE with exit 1. For UTF-16LE it calls buf.subarray(2).toString('utf16le'), which silently drops a trailing odd byte. The same malformed input is treated differently depending on byte order. — fix: Check the length parity after the BOM for both byte orders and refuse odd lengths with the same message. Add a test.
