## High (1)

- **Page-scoped page.route abort is not an egress boundary: redirects, WebSockets, popups and service workers reach non-local hosts** — `src/lib/kit/frame-capture.js:215` (security): The only guard on subresource and navigation egress is page.route('\*\*/\*', ...) on one page. Playwright calls a route handler only for the first URL of a redirect chain, so http://localhost:8080/x that answers 302 to https://other.host is followed without the handler ever seeing the remote URL (the same holds for the --url navigation itself). page.route also does not intercept WebSocket connections (new WebSocket('wss://other.host') needs routeWebSocket), requests made by a service worker, or requests from popups and target=\_blank pages, because the route is attached to the page, not the context. The contract says anything but file:// or localhost/127.0.0.1 is never fetched; a local page under design (which often pulls fonts, CDNs or analytics) will reach outside hosts during capture. — fix: Block at the browser level, not per request: launch Chromium with args \['--host-resolver-rules=MAP \* ~NOTFOUND, EXCLUDE localhost, EXCLUDE 127.0.0.1'\] (or a proxy pointing at a closed port with bypass 'localhost,127.0.0.1'), create the context with serviceWorkers: 'block', and move the route to ctx.route (plus ctx.routeWebSocket aborting non-local URLs) so popups are covered too.

## Medium (4)

- **No test that capture aborts non-local requests from a local page** — `test/kit-deterministic-frame-capture.test.js:184` (test-quality): The stand-in page's route is a no-op (route: async () =\> {}) and the handler passed to it is never invoked or inspected, and the real-playwright test loads a page with no subresources. Nothing checks that a local page's request to a remote host (subresource, redirect, WebSocket) is aborted, which is the security behaviour the contract names ('never fetched'). Deleting line 215 of frame-capture.js would leave every test green. — fix: Have the fake page capture the route handler and assert it calls abort() for https://example.com/x, a redirect target and a non-local WebSocket URL, and continue() for file:// and http://127.0.0.1 URLs; in the real-playwright block, serve a localhost page that redirects to and requests a non-local host and assert no egress.
- **A capture without --loop-ms writes a manifest that seam refuses with exit 1** — `src/lib/kit/frame-capture.js:234` (correctness): --loop-ms is optional for capture (and absent from the contract's capture flags), but without it plan() sets every frame's loop\_t\_ms to null and the manifest stores loop\_ms: null. seamCheck then requires loop\_t\_ms to be a non-negative integer, so \`frame-capture seam --file \<out\>/manifest.json --loop-ms 1000\` on that manifest fails with 'manifest.frames\[0\].loop\_t\_ms must be a non-negative integer' (reproduced with a stand-in playwright). The contract says the manifest records each frame's loop time and that seam checks a saved manifest; the verb's own output is not accepted by its own checker. — fix: Either make --loop-ms required for capture, or have seamCheck derive loop\_t\_ms from t\_ms % loopMs when it is null (and test the capture-then-seam round trip without --loop-ms).
- **Reusing an --out directory leaves stale frames beside the new manifest** — `src/lib/kit/frame-capture.js:206` (correctness): capture accepts an existing directory and only writes frame-00001..frame-N plus manifest.json. A second capture into the same folder with fewer frames (60 then 30) leaves frame-00031.png ... frame-00060.png from the earlier run, so any export that globs frame-\*.png gets a sequence that mixes two runs and breaks the loop seam the manifest reports as clean. — fix: Refuse a non-empty --out (exit 1), or delete existing frame-\*.png files that are not in the new plan before writing the manifest; add a test that captures twice into the same folder.
- **Every animation is set to the global frame time, so animations that start after load jump ahead** — `src/lib/kit/frame-capture.js:225` (correctness): Each frame sets a.currentTime = t for every animation from document.getAnimations(). currentTime is relative to the animation's own start, so this only matches for animations that began at page load. An animation started later (a class added by a timer under the fake clock, an element.animate() call, an entrance triggered at 500 ms) is forced to t instead of t minus its start, so it skips ahead or ends early in the captured frames, and frames no longer match what the page shows at that time. — fix: In the page, keep a WeakMap from animation to the fake time it was first seen and set a.currentTime = t - firstSeen (animations present at load get 0); add a test with a delayed-start animation.
