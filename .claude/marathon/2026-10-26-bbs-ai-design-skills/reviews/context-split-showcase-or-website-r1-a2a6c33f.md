## Medium (4)

- **--file is not checked to be a regular file and is read unbounded** — `src/lib/kit/motion-plan.js:116` (correctness): run() calls fs.stat then fs.readFile with no isFile() check. A FIFO, device or /dev/stdin reports size 0, passes the 8 MiB check, and readFile then reads the stream with no limit (it can hang on an open pipe or pull far more than 8 MiB into memory). The stat/readFile pair is also a TOCTOU: the file can grow after the stat. The Input reading rule in rules.md requires fs.stat(...).isFile() (else exit 1 naming the path) and a bounded read of at most 8 MiB + 1 bytes. The same code is in .claude/helpers/kit/motion-plan.js. — fix: After stat, throw KitExit 1 when !st.isFile(); read through a file handle with a buffer of MAX\_BYTES + 1 and refuse when more than MAX\_BYTES bytes come back. Apply to both copies.
- **stdin is read whole through io.stdin(), not the capped io.stdinBytes** — `src/lib/kit/motion-plan.js:125` (correctness): The verb calls io.stdin() and only checks Buffer.byteLength after the whole stream is in memory, so the 8 MiB cap does not bound the read. cli.js already passes io.stdinBytes, and rules.md says stdin is read with io.stdinBytes({ maxBytes: MAX + 1 }) with the cap counted in bytes. — fix: Read with io.stdinBytes({ maxBytes: MAX\_BYTES + 1 }), refuse when the result is over MAX\_BYTES bytes, then decode as UTF-8. Apply to both copies.
- **--file "" silently falls back to stdin, and a repeated --file is accepted** — `src/lib/kit/motion-plan.js:111` (correctness): With \`--file ""\`, the value '' passes the value check (it does not start with --), file becomes '', and \`if (file)\` is false, so the verb reads stdin instead of refusing. A second --file silently replaces the first. rules.md says an empty flag value and a repeated flag are refused with exit 1. The same code is in .claude/helpers/kit/motion-plan.js. — fix: In the arg loop, throw KitExit 1 when file !== undefined (repeated) or when the value is ''; then test file !== undefined instead of truthiness.
- **Input-reading tests miss what the rule names** — `test/kit-context-split-showcase-or-website.test.js:155` (test-quality): The unit tests drive io.stdin, not stdinBytes. The over-cap case is ASCII only, with no multibyte text, so the bytes-versus-length requirement is never exercised. Nothing covers a FIFO or directory --file, an empty --file value or a repeated --file. The packaged test (test/kit-context-split-showcase-or-website-packaged.test.js) sends every input on stdin and never runs --file through the installed CLI, which rules.md requires. — fix: Give the io helper a stdinBytes, and add an over-cap multibyte case, refusal cases for a directory or /dev/stdin, \`--file ""\` and a repeated --file, plus one packaged run with --file on a temp file.
