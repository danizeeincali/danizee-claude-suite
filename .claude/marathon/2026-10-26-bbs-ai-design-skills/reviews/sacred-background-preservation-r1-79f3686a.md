## High (1)

- **guard passes a flat-colour replacement in an ancestor-qualified or repeated base rule** — `src/lib/kit/bg-fill.js:316` (correctness): A background declaration is only flagged when every matching selector is 'conditional' (own state/qualifier or an at-rule). Ancestor qualifiers (body.dark .bg, .theme-x .bg, #app .bg) and a second plain .bg rule are treated as the base design, so \`.bg{background:url(a.jpg)} body.dark .bg{background:#000}\` and \`.bg{background:url(a.jpg)} .bg{background:#000}\` both return pass:true, exit 0. The contract requires exit 2 when any rule used by the selector replaces the image with a flat colour; dark-theme overrides are exactly that case, so the blocking judge gives a wrong pass on normal CSS (verified with guard()). — fix: Treat the first unconditional rule that sets the background as the design. Flag any later rule or ancestor-qualified rule for the target that changes a BG\_PROP to a different value, and always flag one that flatReplacement() catches. Add tests for \`.dark .bg{background:#000}\` and a repeated \`.bg{background:none}\`.

## Medium (5)

- **Vendor-prefixed -webkit-backdrop-filter / -webkit-filter are never flagged** — `src/lib/kit/bg-fill.js:320` (correctness): decl() keeps the vendor prefix in the property name, but the checks compare it exactly against 'backdrop-filter' and 'filter' (lines 272-274 and 320-321, and FILTER\_PROPS for keyframes at 338). So \`.bg{-webkit-backdrop-filter:blur(8px)}\`, \`.bg{-webkit-filter:blur(8px)}\`, \`transition:-webkit-filter 1s\` and a keyframe that animates -webkit-filter all pass (verified). Safari-targeted frosted panels are often written with the prefix alone, which gives a wrong pass on the frosted-panel rule. — fix: Strip a leading -webkit-/-moz-/-ms-/-o- prefix from the property name (and from transition-property tokens) before the BG\_PROPS/FILTER\_PROPS/TOUCHED lookups, and add a test for each prefixed form.
- **A --selector with an ancestor misses rules that select the same element more broadly** — `src/lib/kit/bg-fill.js:266` (correctness): When the target has a head (\`--selector ".page .hero"\`), a rule is matched only if its own head ends with that head. \`.hero:hover{background:none}\` applies to the same element but is ignored (pass:true), and so is \`.page \> .hero:hover{background:none}\`, because the head '.page \>' does not end with '.page'. Both are wrong passes for a selector shape the CLI accepts. The suffix test \`P.head.endsWith(T.head)\` with no boundary also lets a tag head such as \`page\` match \`.subpage\`, which gives a wrong fail. — fix: Match on the target's last compound first. Treat a rule whose head is less specific than the target's, or which uses a different combinator, as applying to the element, so a background change in it is flagged. Check head suffixes on compound boundaries. Add tests for \`.hero:hover\` and \`.page \> .hero:hover\` against target \`.page .hero\`.
- **Brace matching is quadratic in nesting depth and recursion overflows the stack** — `src/lib/kit/bg-fill.js:131` (performance): walk/ruleBody call matchBrace from every '{' to its close (or to the end of the block when it is unclosed), then recurse into the block and rescan it, so the work is O(depth x n) and the recursion is unbounded. 2 MB of \`a{\` runs for 23 s and then throws RangeError 'Maximum call stack size exceeded'. A 12 KB input of 6000 open braces crashes through the installed CLI with 'kit: Maximum call stack size exceeded', exit 1. This breaks rules.md 'Linear time on capped input' (explicit stack or refuse deep nesting; under 2 s on about 2 MB of adversarial input). — fix: Precompute matching braces in one forward pass with a stack (unclosed ones map to the end). Walk blocks with an explicit stack, or refuse nesting deeper than a fixed limit (e.g. 256) with KitExit 1.
- **Keyframe lookup is animations x frames, not deduplicated** — `src/lib/kit/bg-fill.js:331` (performance): animNames gets one entry per animation declaration, including repeats of the same name. Each entry then filters every keyframes block and walks all of its frame declarations, and the add() dedupe only runs after that work. 30000 \`.bg{animation:k}\` rules plus one @keyframes k with 30000 frames (870 KB) takes 38 s (verified). An 8 MiB cap does not bound that work. — fix: Collect the animation names into a Set and index the keyframes by name in a Map, so each keyframes block is scanned once. Keep the first declaring line only if you need it for messages.
- **No timing test for the guard scanner** — `test/kit-sacred-background-preservation.test.js:1` (test-quality): rules.md 'Linear time on capped input' requires each verb with a scanner to have a timing test: about 2 MB of adversarial input finishing in under 2 s. Neither test file has one, which is why the quadratic brace walk and the keyframe loop above went unnoticed. — fix: Add a test that runs guard() on about 2 MB of deeply nested or unclosed \`a{\`, of repeated animation/keyframes, and of unclosed url( / quotes, and asserts each finishes in under 2 s with exit 0, 2 or a KitExit 1.

## Low (2)

- **Quoted @keyframes names are masked and never matched** — `src/lib/kit/bg-fill.js:190` (correctness): mask() blanks string contents before parsing, so \`@keyframes "pan"\` is stored with the name '" "' and \`animation:"pan" 3s\` never matches it. A quoted keyframes name that animates background-position passes (verified). Quoted names are valid CSS but uncommon. — fix: Read keyframes names and animation-name tokens from the unmasked source at the same offsets, and strip the quotes before comparing.
- **--file is checked with stat on the path, then opened by path** — `src/lib/kit/bg-fill.js:376` (correctness): readFileBounded checks isFile() on the path and then opens the path again. If the path is replaced with a FIFO between the two calls, fs.open blocks and the regular-file guarantee in the Input reading rule is lost. The bounded read limits the size but not this race. — fix: Open first (O\_RDONLY|O\_NONBLOCK), then run fh.stat() on the handle and check isFile() and size there.
