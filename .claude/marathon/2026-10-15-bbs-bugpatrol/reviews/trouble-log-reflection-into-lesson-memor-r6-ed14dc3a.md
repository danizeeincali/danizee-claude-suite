- **words() still splits words at combining marks, so decomposed accents and Indic scripts are scored as fragments** — `src/lib/kit/reflect.js:205` (correctness): The new class /\[^\p{L}\p{N}\s\]/gu keeps letters but not combining marks (\p{M}). An accented word typed in decomposed (NFD) form, which macOS input and some tools produce, still breaks apart: words('Vérifiez la configuration'.normalize('NFD')) gives \['ve','rifiez','la','configuration'\]. overlap() of that text with the same text in NFC is 0.4, below the default threshold of 0.5, so an exact duplicate lesson passes the near-match guard and is saved again. Scripts whose vowel signs are combining marks break up even in NFC: words('परीक्षण से पहले कैश जाँचें') gives \['पर','क','षण','स','पहल','श','ज','च'\]. The same code is in .claude/helpers/kit/reflect.js:205. — fix: Normalise with String(text).normalize('NFC') before lowercasing, and keep marks in the class: /\[^\p{L}\p{M}\p{N}\s\]/gu. Add an NFD-vs-NFC duplicate case and a Devanagari case to the test.
- **Japanese and Chinese lessons, now accepted, get no protection from the near-match guard** — `src/lib/kit/reflect.js:205` (correctness): The diff starts accepting lessons in scripts that do not put spaces between words (the test saves '設定を確認してからデプロイする。'). words() splits only on whitespace, so a whole CJK sentence becomes one token: words('設定を確認してからデプロイする。') is \['設定を確認してからデプロイする'\]. Two lessons that differ by a single character score an overlap of 0. For example, overlap('設定を確認してからデプロイする。','設定を確認してからデプロイしてください。') is 0. So near-duplicates are always saved as new lessons, and the 'confirm by id rather than duplicate' rule in the brief does nothing for these languages. — fix: For runs of Han, Hiragana, Katakana or Thai (\p{Script=Han} etc.), emit character bigrams instead of one token, and add a test that two near-identical Japanese lessons trip the near match.
