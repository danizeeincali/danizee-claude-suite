## Medium (2)

- **A holder whose heartbeat stalls on a slow filesystem loses the lock, then still saves and overwrites the other run's writes** — `src/lib/kit/state-lock.js:187` (correctness): withStateLock never checks that it still owns the lock before fn's write lands. If the holder's heartbeat I/O is slow (a degraded NFS/SMB link, a stalled mount, a blocked event loop), the lock content stays unchanged for staleMs, so a waiter judges it stale, breaks it and does its own load..save. The first holder then resumes and its saveState (triage.js:368/384) writes state it read before the other run, which silently drops that run's records and decisions. The header's 'parallel writers all keep their writes' does not hold, and the 'residual window' note understates this: the loss is not limited to the moment between a breaker's re-read and unlink. Confirmed with two processes, staleMs 300: holder A's heartbeat open('r+') delayed 1.5s and 1.2s of work inside the lock. B broke the lock, read 0 and wrote 1. A then wrote 1 over it. Final {count:1, by:\['A'\]}, so B's write was lost. — fix: Before the write, re-read \<file\>.lock and abort with KitExit 1 ('lost the lock to another run, nothing saved') when the token is no longer ours. For example, pass fn an assertHeld() and call it in visit/decide just before saveState, or do the check inside writeJsonAtomic through an option. Add a test with a slow heartbeat fs like the one above.
- **Dead-pid shortcut breaks a live lock from another machine that has the same hostname, because the pid-namespace id is the same on every Linux host** — `src/lib/kit/state-lock.js:44` (correctness): The shortcut treats a lock as dead when host === os.hostname(), pidns matches and kill(pid,0) gives ESRCH. On Linux, readlink('/proc/self/ns/pid') for the initial namespace is the kernel constant 'pid:\[4026531836\]' (PROC\_PID\_INIT\_INO). It is the same on every machine, and this sandbox returns exactly that. Two hosts with a default or identical hostname ('localhost', 'ubuntu', 'raspberrypi', cloned VMs or CI runners) that share the state file over a network filesystem therefore look like one host. Each sees the other's live holder pid as missing locally and breaks the lock at once, without waiting staleMs. Both then load..save and one run's triage writes are lost. Container pid-namespace inode numbers are also allocated from a small per-boot range, so they can collide across hosts too. The comment at lines 41-43 says the namespace check separates these cases, but it does not. — fix: Add a per-boot machine identity to the lock, such as /proc/sys/kernel/random/boot\_id on Linux (or a random id generated once and kept next to the state on other platforms). Apply the dead-pid shortcut only when host, boot id and pidns all match; otherwise fall back to the observation rule. Add a test where a lock has the same host and pidns but a different boot id.
