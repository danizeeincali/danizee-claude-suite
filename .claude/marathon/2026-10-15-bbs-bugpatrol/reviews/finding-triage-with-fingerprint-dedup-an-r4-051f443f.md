Normalisation only lower-cases the text and masks pure hex runs of 8+ and digit runs of 4+, so mixed tokens survive. That path is not in .gitignore (only .claude/kit/secrets is), so a commit of the working tree publishes it. triage list also prints the members. Confirmed: a violation with element 'AKIAIOSFODNN7EXAMPLE secret=hunter2pass' leaves "members": \["akiaiosfodnn7example secret=hunter2pass"\] in triage.json. Findings from security checks (a hardcoded credential, a token in a page) often carry the offending text as their element. The suite's redact verb exists for exactly this, but triage never uses it. — fix: Store members as hashes, e.g. sha256 of the normalised signature (matching only needs equality), and keep readable labels out of the state; also add .claude/kit/triage.json\* to .gitignore. Add a test asserting that a raw element string never appears in the saved state.

Impact is limited to files named triage.json\*, so this is graded medium, not high. — fix: For the default path (no explicit --state), resolve and write through guarded-fs with root = cwd (or the git toplevel) so a link inside .claude/kit is refused, or at least lstat .claude, .claude/kit and the state file and refuse a symlink.
