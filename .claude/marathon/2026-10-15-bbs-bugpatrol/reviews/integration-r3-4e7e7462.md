## Medium (3)

- **Helper allowance clock is never stopped after an interrupted lead session, so a resumed marathon ends at its first spawn** — `src/plugins/dot-shortcuts.js:4785` (correctness): 4.1a wraps each helper in 'shared-budget start' / 'stop', and 4.2 says that on a resumed stream 'already exists' means keep the file. If the lead session dies, is compacted or restarts (precompact/SessionStart hooks and the launchd/crontab fallback wake exist for exactly this) between start and stop, the state keeps depth \>= 1 and clockRunning: true. Nothing in the text says to inspect or stop it on resume. The downtime is then counted, and every later start/stop pair leaves depth at 1 or more, so the clock never stops. Confirmed with --now: open --time-ms 3600000, start at 0, a resumed start at 7200000 and a stop give depth 1, clockRunning true, elapsedMs 7300000; the next grant returns {skip:true, reason:'time limit exhausted'} with exit 0. The step reads that as 'the allowance is used up: do not spawn, go to CHECKPOINT 5', so the stream stops after a crash with its steps and cost unspent. — fix: On resume (and before the first grant of a session), run 'shared-budget status --state "$S"' and issue 'stop' until depth is 0. Better: do not count wall-clock across sessions; either drop --time-ms from the marathon allowance or record time per helper (from the task notification) through spend.
- **w-review claim budget keeps its path in shell variables across separate Bash calls, so the per-review state degrades to /review-budget.json** — `src/plugins/dot-shortcuts.js:2613` (correctness): The step says to run D=$(mktemp -d) 'at the start of this checkpoint', use B="$D/review-budget.json" for open/grant/spend/release around each sub-session, and run rm -rf "$D" at the end. Those calls are separate Bash tool calls with sub-sessions between them. Claude Code does not keep shell variables between calls, so D is empty in the later calls and B becomes '/review-budget.json'. As a normal user, open fails (EACCES, exit 1), which the text maps to 'broken state, start no more sub-sessions', so no claim is checked. As root (containers, CI), a fixed file at the filesystem root is created; rm -rf "" removes nothing, and Claude Code's own safety check refuses an rm -rf on an empty or unresolvable variable. The next review's open then exits 1 'already exists', which is the cross-run leak that r2 asked to remove. — fix: Have the step print the path (D=$(mktemp -d) && echo "$D") and tell the agent to use that literal path in every later call and in the final rm. Alternatively use a deterministic per-review path such as .claude/kit/review-budget-\<session id\>.json, removed with a guarded \[ -n "$D" \] && rm -rf "$D".
- **check skips the project's doctor checks and passes a broken doctor config** — `bin/cli.js:138` (correctness): check calls runDoctor({profile, cwd, env}) without loading .claude/kit/doctor.json. The doctor verb's run() loads that file. As a result, a project check marked fatal is never run by 'danizee-claude-suite check'. Confirmed: with doctor.json requiring env MY\_REQUIRED\_KEY (fatal), 'kit/cli.js doctor' exits 2 and 'check' exits 0. With an invalid doctor.json ('{bad'), the doctor verb exits 1 and check still exits 0. The row 'Preflight doctor checks -\> cli check' is blocking, and scripts or CI that read check's exit code get 'clean' for a project whose own fatal prerequisite is missing, or whose config is broken. — fix: Use the doctor's run() entry (or load the config the same way: loadConfig(cwd, findProjectRoot(cwd)) and pass custom/customBase) so check honours .claude/kit/doctor.json; map its KitExit 1 to the usage code. Add a reach case with a fatal project check that expects exit 4.
