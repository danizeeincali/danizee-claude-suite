- **Dead-pid shortcut trusts hostname + pidns, but the init pid namespace id is the same on every Linux machine, so a live lock from another machine with the same hostname is broken at once** — `src/lib/kit/state-lock.js:57` (correctness): deadOnThisHost treats a lock as 'on this host' when lock.host === os.hostname() and lock.pidns === readlink('/proc/self/ns/pid'). The pid namespace check added in 16a4f77 does not tell machines apart: the init namespace always reads 'pid:\[4026531836\]' (PROC\_PID\_INIT\_INO is a kernel constant), and this review VM reads exactly that with the generic hostname 'vm'. So two hosts that share the state folder over a network filesystem and have the same hostname (cloned VMs or CI runners, default names such as localhost/ubuntu/vm, containers given the same --hostname) look like one host. A waiter then runs kill(pid,0) against the other machine's pid, gets ESRCH and breaks the live lock immediately. Confirmed: wrote \<state\>.lock as {token:'other-machine', pid:3999999, host:os.hostname(), pidns:\<this pidns\>, beat:7} to stand for a live holder on a twin host, then ran run(\['spend',...\]). It removed the lock and recorded the spend in 41 ms, without waiting staleMs. Both writers then run load..save together, and the lost-update bug from round 1 comes back silently in the multi-host shared-allowance setup the round-3 fix was meant to protect. The header (state-lock.js:17-18) says clock skew 'cannot break a live lock', and that is not true here. Mirrored in .claude/helpers/kit/state-lock.js. The test at test/kit-state-lock.test.js:70 covers only a different pidns string. — fix: Give each machine a real identity in the lock, for example /etc/machine-id or /proc/sys/kernel/random/boot\_id (plus the pidns), and take the dead-pid shortcut only when that id matches. When no machine id can be read, skip the shortcut and fall back to the content-unchanged-for-staleMs rule. Add a test where a lock has the same hostname and pidns but a different machine/boot id, and assert that it waits the full staleMs.
