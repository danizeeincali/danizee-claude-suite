- **On the old Node versions it exists to catch, the node-version check never runs: the kit CLI crashes first** — `.claude/helpers/kit/doctor.js:98` (correctness): doctor is reached only through cli.js, whose loadVerbs imports every sibling module before dispatching (cli.js:24-26). diff-range.js sorts ahead of doctor.js and has \`import { isUtf8 } from 'buffer'\`, an export that exists only from Node 18.14 / 19.4. On Node 16 or 18.0-18.13, linking fails, and main() rejects with no catch. \`cli.js doctor\` then prints a raw 'SyntaxError: The requested module 'buffer' does not provide an export named ...' stack trace and exits 1 (invalid input). It never prints the fatal node-version row with 'Install node 20 or newer' and never exits 2. I confirmed this on Node 22 by renaming the import in a copy of the kit: doctor exited 1 with exactly that stack and no JSON. A preflight whose first fatal check is the Node floor fails without a usable message in the very environment that check targets, and no test runs doctor through the CLI with an old version. — fix: Make doctor reachable before the other verbs load. Either have cli.js check process.version against 20 (or import doctor.js directly for the doctor verb) before loadVerbs, or have loadVerbs catch a module's import error and skip that verb. Add a test that fakes an unloadable sibling module and asserts doctor still answers.
- **The optional gh-login check the spec names is not implemented; the review profile only checks that gh is on PATH** — `.claude/helpers/kit/doctor.js:177` (correctness): The deliverable says the doctor adds 'optional gh login' among its named checks, and the idea lists 'a logged-out GitHub CLI' as an advisory warning. The review profile only looks gh up on PATH (header line 13: 'presence only'). With gh installed but logged out, or with an expired token, \`doctor --profile review\` reports ok with no warnings. The review workflow then fails later at its first gh call. This happens most often on a fresh or offline machine, which is when a preflight should warn. A login state can be detected without any network call, by reading GH\_TOKEN/GITHUB\_TOKEN or gh's hosts.yml, so the no-network rule does not prevent it. — fix: Add an advisory 'gh-auth' row to the review profile. It passes when GH\_TOKEN or GITHUB\_TOKEN is set, or when gh's hosts.yml (in GH\_CONFIG\_DIR, else XDG\_CONFIG\_HOME/gh, else ~/.config/gh) lists a host with a user. It never prints a value, spawns nothing and makes no network call. Test both outcomes.
